# 第 19 题 · 隔离跨命名空间服务流量

建议用时 18 分钟，环境准备完成后开始计时。

操作入口 `kubectl config use-context kind-cka-next`。Context 为 `kind-cka-next`，命名空间为 `cka-19`。

## 题目主干

在 `cka-19` 中创建 NetworkPolicy `ledger-ingress`，隔离所有 `app=ledger` 后端的入站流量。只允许位于 `access-zone=trusted` 命名空间、且具有 `role=reader` 标签的 Pod 访问 TCP 80。保留 Deployment、Service 和原有标签，不新增出站限制。

## 官方参考

- [Network Policies](https://kubernetes.io/docs/concepts/services-networking/network-policies/) · 入站规则及两类 selector 的组合。
- [kind 发布说明](https://github.com/kubernetes-sigs/kind/releases/tag/v0.24.0) · kindnetd 的基础 NetworkPolicy 支持。

## 验收标准

```sh
kubectl -n cka-19-client exec allowed -- wget -qO- -T 4 http://ledger.cka-19.svc.cluster.local/
kubectl -n cka-19-client exec wrong-role -- wget -qO- -T 4 http://ledger.cka-19.svc.cluster.local/
kubectl -n cka-19 exec wrong-namespace -- wget -qO- -T 4 http://ledger.cka-19.svc.cluster.local/
```

等待 CNI 生效后，第一条返回 Nginx 首页，后两条返回非零退出码。三个客户端均保持 Ready。
