# 第 30 题 · 解题思路

## 关键技术难点

证书主体的 CN 映射到 Kubernetes 用户名。本题 RoleBinding 已限定该用户名和作用域。审批 CSR 后还需等待签发，再用独立 kubeconfig 验证，以实际 API 请求确认身份。

## 解题顺序与答案详解

在临时目录创建密钥和 CSR。下列 heredoc 仅用于作答。注意命令中的续行和字段缩进。

```sh
umask 077
openssl req -new -newkey rsa:2048 -nodes -keyout viewer.key -out viewer.csr -subj '/CN=cka-30-viewer'
request=$(base64 < viewer.csr | tr -d '\n')
kubectl --context kind-cka-next apply -f - <<EOF
apiVersion: certificates.k8s.io/v1
kind: CertificateSigningRequest
metadata:
  name: cka-30-viewer
spec:
  request: $request
  signerName: kubernetes.io/kube-apiserver-client
  expirationSeconds: 86400
  usages:
  - client auth
EOF
kubectl --context kind-cka-next certificate approve cka-30-viewer
kubectl --context kind-cka-next wait --for=jsonpath='{.status.certificate}' csr/cka-30-viewer --timeout=60s
kubectl --context kind-cka-next get csr cka-30-viewer -o jsonpath='{.status.certificate}' | openssl base64 -d -A > viewer.crt
```

仅从管理员配置提取本地 API 地址和 CA，再写入专用配置。

```sh
server=$(kubectl --context kind-cka-next config view --minify -o jsonpath='{.clusters[0].cluster.server}')
kubectl --context kind-cka-next config view --raw --flatten --minify -o jsonpath='{.clusters[0].cluster.certificate-authority-data}' | openssl base64 -d -A > ca.crt
kubectl --kubeconfig viewer.kubeconfig config set-cluster lab --server="$server" --certificate-authority=ca.crt --embed-certs=true
kubectl --kubeconfig viewer.kubeconfig config set-credentials cka-30-viewer --client-key=viewer.key --client-certificate=viewer.crt --embed-certs=true
kubectl --kubeconfig viewer.kubeconfig config set-context viewer --cluster=lab --user=cka-30-viewer --namespace=cka-30
kubectl --kubeconfig viewer.kubeconfig config use-context viewer
```

使用题面命令验证。如果 CSR 已批准但证书字段为空，检查 signer、usages 及控制器状态。
