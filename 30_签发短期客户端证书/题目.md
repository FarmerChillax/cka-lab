# 第 30 题 · 签发短期客户端证书并验证权限

建议用时 24 分钟，环境准备完成后开始计时。

操作入口 `kubectl config use-context kind-cka-next`。Context 为 `kind-cka-next`，命名空间为 `cka-30`。

## 题目主干

为用户 `cka-30-viewer` 签发请求时长为 86400 秒的客户端证书。CSR 对象名与用户名相同。生成独立 `viewer.kubeconfig`，其中默认命名空间为 `cka-30`。用实际证书证明该用户只能在本题命名空间列出 ConfigMap，不能读取 Secret 或在 default 列出 ConfigMap。保留既有 RBAC。

## 官方参考

- [Kubernetes CSR](https://kubernetes.io/docs/reference/access-authn-authz/certificate-signing-requests/) · 客户端 signer、审批和证书读取。
- [配置 kubeconfig](https://kubernetes.io/docs/tasks/access-application-cluster/configure-access-multiple-clusters/) · 独立凭据与上下文。
- [配置客户端证书](https://kubernetes.io/docs/tasks/tls/certificate-issue-client-csr/) · 从 CSR 申请 API 客户端证书。

## 验收标准

```sh
kubectl get csr cka-30-viewer
kubectl --kubeconfig viewer.kubeconfig auth whoami
kubectl --kubeconfig viewer.kubeconfig get configmaps
kubectl --kubeconfig viewer.kubeconfig auth can-i get secrets
kubectl --kubeconfig viewer.kubeconfig auth can-i list configmaps -n default
```

CSR 显示 Approved 和 Issued，身份为 cka-30-viewer，本题 ConfigMap 可列出，最后两项为 no。
