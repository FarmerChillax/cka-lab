# 第 17 题：解题思路

## 关键技术难点

初始单个 Pod 请求 300m CPU，配额总计仅允许 500m，因此第二个 Pod 会被拒绝。把请求改为 150m 后三个副本合计为 450m，但默认 RollingUpdate 还会尝试创建 surge Pod；`count/pods: 3` 可能使更新停滞。`Recreate` 会先终止旧 ReplicaSet 的 Pod，再创建新版本。

## 答案详解

先从 ReplicaSet 事件和 quota 用量定位原因：

```sh
kubectl -n cka-quota describe replicaset
kubectl -n cka-quota describe resourcequota application-budget
kubectl -n cka-quota get limitrange container-cpu -o yaml
```

原子修改更新策略和资源值：

```sh
kubectl -n cka-quota patch deployment processor --type=json \
  -p='[
    {"op":"replace","path":"/spec/strategy/type","value":"Recreate"},
    {"op":"remove","path":"/spec/strategy/rollingUpdate"},
    {"op":"replace","path":"/spec/template/spec/containers/0/resources/requests/cpu","value":"150m"},
    {"op":"replace","path":"/spec/template/spec/containers/0/resources/limits/cpu","value":"300m"}
  ]'

kubectl -n cka-quota rollout status deployment/processor --timeout=2m
```

验证三个副本及配额用量：

```sh
kubectl -n cka-quota get deploy processor
kubectl -n cka-quota describe quota application-budget
kubectl -n cka-quota get pods -l app=processor
```

如果 JSON patch 报告 `rollingUpdate` 路径不存在，可去掉对应 remove 操作后重试。最终 request 和 limit 都满足 LimitRange 的最小值、最大值，也没有超过 ResourceQuota。
