# 第 17 题：修复配额阻塞的 Deployment 更新

**建议用时：** 20 分钟。**Context：** `kind-cka-lab`。**命名空间：** `cka-quota`。

## 题目主干

Deployment `processor` 期望运行 3 个副本，但 ResourceQuota 阻止了 Pod 创建。修复工作负载并满足：

1. 不得修改或删除 ResourceQuota `application-budget`；
2. 不得修改或删除 LimitRange `container-cpu`；
3. Deployment 副本数保持为 3，镜像保持不变；
4. 每个容器最终设置 CPU request `150m`、CPU limit `300m`；
5. 选择一种不会因滚动更新的额外 Pod 而再次被 `count/pods: 3` 阻塞的更新策略；
6. 最终 Deployment 达到 `3/3` Ready。

官方参考：

- https://kubernetes.io/docs/concepts/policy/resource-quotas/
- https://kubernetes.io/docs/concepts/policy/limit-range/
- https://kubernetes.io/docs/concepts/workloads/controllers/deployment/#strategy

## 验收标准

```sh
kubectl -n cka-quota get deployment processor
kubectl -n cka-quota get deployment processor -o yaml
kubectl -n cka-quota describe resourcequota application-budget
kubectl -n cka-quota get pods -l app=processor
```

预期 Deployment 为 `3/3`，策略为 `Recreate`，三个 Pod 合计使用 CPU requests 450m、CPU limits 900m，且两个策略资源仍存在。
