# 第 1 题：解题思路

## 关键技术难点

1. Pod 已运行不代表 Ready。readiness probe 请求不存在的 `/ready` 路径，导致容器无法被视为就绪。
2. Service selector 必须与 Pod 标签匹配。本题 Service 使用 `app=catalog-v2`，Pod 使用 `app=catalog`。
3. 两个故障叠加：只修复其中一处仍无法恢复 Service 流量。需要结合 Pod 事件、标签和 EndpointSlice 定位。

## 排查与实施顺序

1. 确认 context 和命名空间，查看 Pod Ready 状态及 Deployment 副本状态。
2. 查看 Pod 事件，判断探针是否失败，并核对探针路径与应用实际服务路径。
3. 对比 Service selector 与 Pod 标签；查看 EndpointSlice 是否存在可用后端。
4. 分别修复探针和 selector，等待滚动更新完成。
5. 按题目中的验收标准从集群内验证 HTTP 响应。

## 答案详解

### 操作步骤

```sh
kubectl -n cka-lab get pods -l app=catalog
kubectl -n cka-lab describe pods -l app=catalog
kubectl -n cka-lab get deployment catalog -o yaml
kubectl -n cka-lab get service catalog -o yaml
```

Nginx 默认首页位于 `/`。初始 readiness probe 请求 `/ready`，因此 Pod 不能就绪。Service 的 selector 为 `app=catalog-v2`，也匹配不到标签为 `app=catalog` 的 Pod。修复这两处：

```sh
kubectl -n cka-lab patch deployment catalog --type=json \
  -p='[{"op":"replace","path":"/spec/template/spec/containers/0/readinessProbe/httpGet/path","value":"/"}]'

kubectl -n cka-lab patch service catalog --type=merge \
  -p='{"spec":{"selector":{"app":"catalog"}}}'
```

只修复探针或只修复 selector 均不足以完成本题。readiness probe 失败时，Pod 不会作为匹配 Service 的可用后端。
