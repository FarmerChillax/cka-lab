# 第 15 题：解题思路

## 关键技术难点

安装和升级必须针对同一个 release。若第二次执行 `helm install` 会因名称已存在而失败；直接使用 `kubectl edit` 又会使 Helm 保存的 release 配置与集群资源不一致。

## 答案详解

先安装默认 revision：

```sh
helm install reporting ./chart \
  --namespace cka-helm \
  --wait --timeout 2m
```

再用 values 覆盖升级：

```sh
helm upgrade reporting ./chart \
  --namespace cka-helm \
  --set replicaCount=2 \
  --set image.tag=1.27.5 \
  --set service.type=ClusterIP \
  --set service.port=8080 \
  --wait --timeout 2m
```

验证 Helm 保存的值与实际资源：

```sh
helm history reporting -n cka-helm
helm get values reporting -n cka-helm
kubectl -n cka-helm get deploy reporting \
  -o jsonpath='{.spec.replicas}{" "}{.spec.template.spec.containers[0].image}{"\n"}'
kubectl -n cka-helm get svc reporting \
  -o jsonpath='{.spec.type}{" "}{.spec.ports[0].port}{" "}{.spec.ports[0].targetPort}{"\n"}'
```

`--wait` 只在资源满足就绪条件后返回。`helm history` 应显示两个成功 revision，最终 values 应只包含升级时设置的覆盖值。
