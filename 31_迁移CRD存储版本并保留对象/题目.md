# 第 31 题 · 迁移 CRD 存储版本并保留对象

建议用时 25 分钟，环境准备完成后开始计时。

操作入口 `kubectl config use-context kind-cka-next`。Context 为 `kind-cka-next`，命名空间为 `cka-31`。

## 题目主干

CRD `schedules.practice.cka.example` 已同时提供 v1beta1 和 v1，当前有两条以旧版本存储的对象。将存储版本改为 v1，重写两条对象，再退役 v1beta1。在整个迁移中保留 CRD 和对象的 UID 与 spec 值。可添加迁移标记 annotation 作为写入证据。

## 官方参考

- [Versions in CustomResourceDefinitions](https://kubernetes.io/docs/tasks/extend-kubernetes/custom-resources/custom-resource-definition-versioning/) · 存储版本迁移、手动改写对象和移除旧版本。
- [Storage Versions](https://kubernetes.io/docs/concepts/overview/working-with-objects/storage-version/) · 区分读取转换与持久化版本。

## 验收标准

```sh
kubectl get crd schedules.practice.cka.example -o jsonpath='{.spec.versions[*].name}{" "}{.status.storedVersions}{"\n"}'
kubectl -n cka-31 get schedules.v1.practice.cka.example -o custom-columns=NAME:.metadata.name,UID:.metadata.uid,WINDOW:.spec.window
kubectl get --raw=/apis/practice.cka.example/v1beta1
```

CRD 的 spec 和 status 只保留 v1，daily 和 weekly 的原 UID 与值保持一致。旧 API 路径返回 NotFound。
