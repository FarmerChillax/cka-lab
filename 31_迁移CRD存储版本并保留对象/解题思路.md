# 第 31 题 · 解题思路

## 关键技术难点

读 v1 只是 API 转换。已有对象只有被写回后才使用新的存储版本。删除旧版本前必须先确认所有对象都被重写，然后更新 storedVersions。

## 解题顺序与答案详解

记录初始 UID 和 spec。清单中的 v1beta1 在索引 0，v1 在索引 1。保持旧版本可读，先切换存储版本。

```sh
kubectl -n cka-31 get schedules.v1beta1.practice.cka.example -o yaml
kubectl patch crd schedules.practice.cka.example --type=json -p '[{"op":"replace","path":"/spec/versions/0/storage","value":false},{"op":"replace","path":"/spec/versions/1/storage","value":true}]'
kubectl get crd schedules.practice.cka.example -o jsonpath='{.status.storedVersions}{"\n"}'
```

确认 storedVersions 已同时包含两个版本。枚举所有命名空间的对象，准备中的对象应只有 daily 和 weekly。通过 v1 API 做可观察的实际写入，再移除旧版本。

```sh
kubectl get schedules.v1.practice.cka.example -A
kubectl -n cka-31 annotate schedules.v1.practice.cka.example daily weekly cka.example/storage-migrated=v1 --overwrite
kubectl patch crd schedules.practice.cka.example --subresource=status --type=merge -p '{"status":{"storedVersions":["v1"]}}'
kubectl patch crd schedules.practice.cka.example --type=json -p '[{"op":"remove","path":"/spec/versions/0"}]'
```

若还存在其他对象，先同样重写再更新 status。用题面的自定义列核对 UID 和 spec，并确认旧路径已关闭。
