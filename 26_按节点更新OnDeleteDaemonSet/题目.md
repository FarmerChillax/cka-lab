# 第 26 题 · 按节点更新 OnDelete DaemonSet

建议用时 17 分钟，环境准备完成后开始计时。

操作入口 `kubectl config use-context kind-cka-next`。Context 为 `kind-cka-next`，命名空间为 `cka-26`。

## 题目主干

将 DaemonSet `node-observer` 的 `OBSERVATION_MODE` 从 basic 更新为 detailed。保留 OnDelete 策略。先更新 `cka-next-worker` 上的 Pod 并等它 Ready，再更新 `cka-next-worker2` 上的 Pod。最终仅在两个工作节点各运行一个新版 Pod。

## 官方参考

- [DaemonSet](https://kubernetes.io/docs/concepts/workloads/controllers/daemonset/) · 节点范围、Pod 模板与控制器。
- [DaemonSet 更新](https://kubernetes.io/docs/tasks/manage-daemon/update-daemon-set/) · 更新策略和逐节点验证。

## 验收标准

```sh
kubectl -n cka-26 get ds node-observer
kubectl -n cka-26 get pods -l app=node-observer -o wide
for pod in $(kubectl -n cka-26 get pods -l app=node-observer -o name); do
  kubectl -n cka-26 exec "$pod" -- printenv OBSERVATION_MODE
done
```

DaemonSet 的 DESIRED、READY、UP-TO-DATE 均为 2，两个 Pod 都输出 detailed。
