# 第 9 题：解题思路与答案详解

## 关键技术难点

1. 不可变 ConfigMap 和 Secret 不能原地修改，只能创建新名字并切换消费者引用。
2. Secret 数据必须通过 `secretKeyRef` 或卷引用进入容器，不能写进 Deployment 的普通 `value`。
3. projected 卷的 `defaultMode` 使用整数；十进制 `256` 等价于八进制 `0400`。

## 解题思路

先创建两个 v2 对象，再一次性更新 Deployment 中的环境变量引用、卷来源和文件模式。等待滚动更新完成后，从新 Pod 内同时验证环境变量、文件内容与权限。

## 答案详解

将以下内容保存为临时文件 `rotation.yaml` 并应用：

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: report-config-v2
  namespace: cka-config
immutable: true
data:
  app.properties: |
    MODE=production
    REPORT_PATH=/srv/reports
---
apiVersion: v1
kind: Secret
metadata:
  name: report-credentials-v2
  namespace: cka-config
immutable: true
type: Opaque
stringData:
  username: reporter-v2
  password: cka-rotate-2026
```

```sh
kubectl apply -f rotation.yaml
kubectl -n cka-config edit deployment report-api
```

在编辑器中把两个 `secretKeyRef.name` 改成 `report-credentials-v2`，把 projected 卷的 ConfigMap 和 Secret 名改成 v2，并在 `projected` 下增加 `defaultMode: 256`。目标卷片段如下：

```yaml
volumes:
- name: runtime-config
  projected:
    defaultMode: 256
    sources:
    - configMap:
        name: report-config-v2
        items:
        - key: app.properties
          path: app.properties
    - secret:
        name: report-credentials-v2
        items:
        - key: username
          path: credentials/username
        - key: password
          path: credentials/password
```

最后运行题面验收命令。若 Pod 一直无法启动，先用 `kubectl -n cka-config describe pod` 检查引用的对象名和键名；如果 `stat` 显示 `444`，说明 `defaultMode` 没有放在 `projected` 层级。

2. `report-config-v2` 为不可变 ConfigMap，`app.properties` 正确包含 `MODE=production` 和 `REPORT_PATH=/srv/reports` 两行。
3. `report-credentials-v2` 为不可变 Secret，实际环境变量输出为 `reporter-v2 cka-rotate-2026`，两个新凭据均已生效。
4. Deployment 当前修订版本为 2，滚动更新成功，Ready 副本数为 2；Pod `report-api-889b48888-jtqqv` 和 `report-api-889b48888-vqdcq` 均为 `1/1 Running`。
5. `DB_USERNAME` 和 `DB_PASSWORD` 均通过 `secretKeyRef` 引用 v2 Secret，没有把凭据明文写入 Pod template；投射卷的 ConfigMap 和 Secret 来源也都已切换到 v2。
6. Pod 内的 `app.properties` 内容正确，但投射卷设置了 `defaultMode: 400`。该 JSON/YAML 整数值是十进制 400，对应八进制权限 `0620`，不是题目要求的 `0400`。
7. 使用 `stat -L` 跟随符号链接后，`app.properties`、`credentials/username` 和 `credentials/password` 三个目标文件的权限均为 `620`，因此权限验收未通过。应将 `defaultMode` 改为十进制 `256` 或 YAML 八进制写法 `0400`，并完成新的滚动更新。

补充说明：题面原验收命令中的 `stat -c` 不跟随符号链接，因此顶层的 `/etc/report/app.properties` 会显示链接自身的 `777`。检查投射目标文件权限应使用 `stat -L -c`；本次即使跟随链接后仍为 `620`，所以不影响“权限未通过”的判定。

本次作答正确完成了不可变 v2 对象创建、凭据引用、投射卷切换和滚动更新，唯一未满足项是文件权限设置。
