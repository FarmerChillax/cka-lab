# 第 9 题：解题思路与答案详解

## 关键技术难点

1. 不可变 ConfigMap 和 Secret 不能原地修改，只能创建新名字并切换消费者引用。
2. Secret 数据必须通过 `secretKeyRef` 或卷引用进入容器，不能写进 Deployment 的普通 `value`。
3. projected 卷的 `defaultMode` 使用整数；十进制 `256` 等价于八进制 `0400`。

## 解题思路

先创建两个 v2 对象，再一次性更新 Deployment 中的环境变量引用、卷来源和文件模式。等待滚动更新完成后，从新 Pod 内同时验证环境变量、文件内容与权限。

## 答案详解

将以下内容保存为临时文件 `rotation.yaml` 并应用：

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: report-config-v2
  namespace: cka-config
immutable: true
data:
  app.properties: |
    MODE=production
    REPORT_PATH=/srv/reports
---
apiVersion: v1
kind: Secret
metadata:
  name: report-credentials-v2
  namespace: cka-config
immutable: true
type: Opaque
stringData:
  username: reporter-v2
  password: cka-rotate-2026
```

```sh
kubectl apply -f rotation.yaml
kubectl -n cka-config edit deployment report-api
```

在编辑器中把两个 `secretKeyRef.name` 改成 `report-credentials-v2`，把 projected 卷的 ConfigMap 和 Secret 名改成 v2，并在 `projected` 下增加 `defaultMode: 256`。目标卷片段如下：

```yaml
volumes:
- name: runtime-config
  projected:
    defaultMode: 256
    sources:
    - configMap:
        name: report-config-v2
        items:
        - key: app.properties
          path: app.properties
    - secret:
        name: report-credentials-v2
        items:
        - key: username
          path: credentials/username
        - key: password
          path: credentials/password
```

最后运行题面验收命令。若 Pod 一直无法启动，先用 `kubectl -n cka-config describe pod` 检查引用的对象名和键名；如果 `stat` 显示 `444`，说明 `defaultMode` 没有放在 `projected` 层级。
