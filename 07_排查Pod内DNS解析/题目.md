# 第 7 题：排查 Pod 内 DNS 解析

**建议用时：** 18 分钟。**Context：** `kind-cka-lab`。**命名空间：** `cka-dns`。

**操作入口：** `kubectl config use-context kind-cka-lab`

## 题目主干

`backend` Deployment 和 Service 均正常，但 `dns-client` Pod 无法通过 Service DNS 名称访问后端。排查并修复**客户端工作负载的 DNS 配置**，使 Pod 既能解析短名称 `backend`，也能解析完整名称 `backend.cka-dns.svc.cluster.local`，并能通过 HTTP 访问后端。

保留 `backend` Deployment、Service 和 `dns-client` Deployment 的名称与副本数；不得修改 `kube-system` 中的 CoreDNS 资源，不得将 Service ClusterIP 写死到客户端配置中。

## 题面引用信息

| 项目 | 给定值 |
| --- | --- |
| 客户端 Deployment | `cka-dns/dns-client`，1 个副本 |
| 后端 Deployment / Service | `cka-dns/backend`，各 1 个 |
| 短名称 / FQDN | `backend` / `backend.cka-dns.svc.cluster.local` |

官方参考：[DNS for Services and Pods](https://kubernetes.io/docs/concepts/services-networking/dns-pod-service/) 中的 **Namespaces of Services**、**Pod's DNS Policy**、**Pod's DNS Config**；[Pod API 参考](https://kubernetes.io/docs/reference/kubernetes-api/core/pod-v1/) 中的 `dnsPolicy` 与 `dnsConfig` 字段。

## 验收标准

```sh
kubectl -n cka-dns rollout status deployment/dns-client --timeout=120s
kubectl -n cka-dns exec deployment/dns-client -- nslookup backend
kubectl -n cka-dns exec deployment/dns-client -- \
  nslookup backend.cka-dns.svc.cluster.local
kubectl -n cka-dns exec deployment/dns-client -- \
  wget -qO- http://backend.cka-dns.svc.cluster.local
```

两次 DNS 查询应返回 `backend` Service 的 ClusterIP；HTTP 请求应输出 Nginx 首页。只要最终状态满足要求，可以通过 Deployment 滚动更新替换客户端 Pod。
