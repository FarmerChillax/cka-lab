# 环境准备：排查 Pod 内 DNS 解析

需要 `kind` v0.33.0 或更新版本、`kubectl` 和已启动的 kind 兼容容器运行时。kind 默认自动选择可用运行时。本题沿用 `cka-lab` 集群；已有集群时跳过创建。

从仓库根目录进入本题目录：

```sh
cd 07_排查Pod内DNS解析
```

集群配置见 [kind-config.yaml](kind-config.yaml)。仅在集群不存在时执行：

```sh
kind create cluster --name cka-lab --config kind-config.yaml --wait 5m
```

应用 [setup.yaml](setup.yaml) 准备后端 Service 和待排查的客户端 Deployment。初始配置有意使客户端无法使用集群 DNS；不要在准备阶段修复。

```sh
kubectl config use-context kind-cka-lab
kubectl get nodes
kubectl apply -f setup.yaml
kubectl -n cka-dns rollout status deployment/backend --timeout=120s
kubectl -n cka-dns rollout status deployment/dns-client --timeout=120s
kubectl -n cka-dns get deployment,service,pod
```

两个 Deployment 均已就绪后，开始本题的 18 分钟计时。`dns-client` 的容器 Ready 只表示进程运行，不代表 DNS 解析正常。

重练时先确认 context，再删除本题命名空间并重新应用 `setup.yaml`：

```sh
kubectl config current-context
kubectl delete namespace cka-dns --ignore-not-found --wait=true
kubectl apply -f setup.yaml
```
