# 第 7 题：解题思路与答案详解

## 关键技术难点

1. Pod `Running`/`Ready` 不代表其 DNS 设置正确。先确认 Service 和后端，再查看客户端 `/etc/resolv.conf`。
2. `dnsPolicy: None` 让 Pod 忽略集群 DNS 设置；自定义 `dnsConfig.nameservers` 会指定另一个 DNS 服务器。
3. 修改 Deployment 的 Pod 模板后会滚动创建新 Pod；现有 Pod 的 DNS 设置不会原地改变。

## 解题思路

对比 Service、后端 EndpointSlice 与客户端 DNS 配置，确认故障限于客户端；修正 Deployment Pod 模板中的 DNS 策略并移除错误的覆盖项，等待滚动更新后验证短名称、FQDN 和 HTTP。

## 答案详解

```sh
kubectl -n cka-dns get service backend
kubectl -n cka-dns get endpointslice -l kubernetes.io/service-name=backend
kubectl -n cka-dns get deployment dns-client -o yaml
kubectl -n cka-dns exec deployment/dns-client -- cat /etc/resolv.conf
```

初始客户端使用 `dnsPolicy: None`，且名字服务器是测试网段地址 `203.0.113.53`。将其恢复为集群 DNS，并移除自定义 DNS 配置：

```sh
kubectl -n cka-dns patch deployment dns-client --type=json \
  -p='[{"op":"replace","path":"/spec/template/spec/dnsPolicy","value":"ClusterFirst"},{"op":"remove","path":"/spec/template/spec/dnsConfig"}]'
kubectl -n cka-dns rollout status deployment/dns-client --timeout=120s
kubectl -n cka-dns exec deployment/dns-client -- nslookup backend
kubectl -n cka-dns exec deployment/dns-client -- nslookup backend.cka-dns.svc.cluster.local
kubectl -n cka-dns exec deployment/dns-client -- wget -qO- http://backend.cka-dns.svc.cluster.local
```

两次 `nslookup` 应指向同一 Service ClusterIP，`wget` 应取得 Nginx 首页。若仍失败，检查新 Pod 的 `/etc/resolv.conf`、`kube-system` 的 `kube-dns` Service 与 CoreDNS Pod 状态；本题正常情况下无须更改 CoreDNS。
