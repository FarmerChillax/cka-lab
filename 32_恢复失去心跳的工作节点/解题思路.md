# 第 32 题 · 解题思路

## 关键技术难点

节点 Ready 状态与 Lease 可反映 kubelet 心跳。原有容器可能在 kubelet 停止后继续运行，因此要验证新的 Pod 确实能启动。

## 解题顺序与答案详解

先从 API 查看节点条件，再检查目标节点容器的 systemd 单元。确认 kubelet 未运行后，启动服务并检验新 Pod。

```sh
kubectl describe node cka-kubelet-worker2
podman exec cka-kubelet-worker2 systemctl status kubelet --no-pager || true
podman exec cka-kubelet-worker2 journalctl -u kubelet -n 40 --no-pager
podman exec cka-kubelet-worker2 systemctl start kubelet
kubectl wait --for=condition=Ready node/cka-kubelet-worker2 --timeout=120s
kubectl -n cka-32 rollout restart deployment/canary
kubectl -n cka-32 rollout status deployment/canary --timeout=120s
```

如果服务仍无法启动，先读 journalctl 最近的错误，再检查容器运行时与 kubelet 配置。systemctl status 对未运行的服务会返回非零状态。

对照[题面验收标准](题目.md)检查最终状态。
