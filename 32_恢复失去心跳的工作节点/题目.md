# 第 32 题 · 恢复失去心跳的工作节点

建议用时 23 分钟，环境准备完成后开始计时。

操作入口 `kubectl config use-context kind-cka-kubelet`。Context 为 `kind-cka-kubelet`，命名空间为 `cka-32`。

## 题目主干

工作节点 `cka-kubelet-worker2` 已丢失心跳。检查节点条件及节点上相关服务日志，恢复 kubelet。恢复后让 `canary` Deployment 重新滚动一次，验证能够创建新 Pod。保持节点容器、Deployment 节点选择和副本数。

## 官方参考

- [Troubleshooting Clusters](https://kubernetes.io/docs/tasks/debug/debug-cluster/) · 节点状态与 kubelet 日志。
- [Nodes](https://kubernetes.io/docs/concepts/architecture/nodes/#node-status) · Ready、心跳和节点租约。

## 验收标准

```sh
kubectl wait --for=condition=Ready node/cka-kubelet-worker2 --timeout=120s
kubectl -n kube-node-lease get lease cka-kubelet-worker2
kubectl -n cka-32 rollout status deployment/canary --timeout=120s
kubectl -n cka-32 get pods -l app=canary -o wide
```

节点为 Ready，Lease 持续续约，新的 canary Pod 在 worker2 上 Running 且 Ready。
