# 环境准备 · 恢复失去心跳的工作节点

准备 kind v0.33.0 或更新版本、kubectl 和已启动的容器运行时。kind 自动选择 Docker、Podman 或 nerdctl。在仓库根目录进入本题目录，随后用下列命令创建集群。已有同名 kind 集群时可以跳过创建。

```sh
cd 32_恢复失去心跳的工作节点
kind create cluster --name cka-kubelet --config kind-config.yaml --wait 5m
```

本目录的 [kind-config.yaml](kind-config.yaml) 定义节点布局。本题使用独立集群。需要在 kind 节点容器中执行管理命令。以下以 Podman 为例，若 kind 选择了 Docker 或 nerdctl，将 `podman` 换成对应 CLI。先用 `kind get nodes --name cka-kubelet` 核对目标。

用 [setup.yaml](setup.yaml) 建立初始资源，再核对初始状态。

```sh
kubectl config use-context kind-cka-kubelet
kubectl --context kind-cka-kubelet apply -f setup.yaml
kubectl -n cka-32 rollout status deployment/canary --timeout=120s
podman exec cka-kubelet-worker2 systemctl stop kubelet
kubectl wait --for=condition=Ready=Unknown node/cka-kubelet-worker2 --timeout=120s
kubectl get nodes
```

重练时可以删除独立集群 `kind delete cluster --name cka-kubelet`，再执行准备步骤。
