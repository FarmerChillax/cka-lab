# 第 36 题 · 修复非 root 容器的共享卷写入

建议用时 20 分钟。准备完成后开始计时。

操作入口 `kubectl config use-context kind-cka-next`，命名空间 `cka-36`。

## 题目主干

`spooler` 的初始化容器已创建共享目录，但业务容器 `writer` 启动失败。通过 Pod 模板使共享卷使用组 ID 2000，并让 writer 有权写入。保留 writer 的 UID、主 GID 和非 root 约束，保留卷类型、初始化命令与 `2770` 目录模式。

## 官方参考

- [Configure a Security Context](https://kubernetes.io/docs/tasks/configure-pod-container/security-context/#set-the-security-context-for-a-pod) · Pod 的 fsGroup 与补充组。
- [emptyDir](https://kubernetes.io/docs/concepts/storage/volumes/#emptydir) · Pod 内共享卷生命周期。

## 验收标准

```sh
kubectl -n cka-36 rollout status deploy/spooler --timeout=120s
kubectl -n cka-36 exec deploy/spooler -c writer -- id
kubectl -n cka-36 exec deploy/spooler -c writer -- ls -ldn /spool/inbox
kubectl -n cka-36 exec deploy/spooler -c writer -- cat /spool/inbox/ready
```

Deployment 达到 1/1。writer 的 UID 和主 GID 均为 10001，补充组包含 2000。目录的 GID 为 2000，文件内容为 `spool-ok`。
