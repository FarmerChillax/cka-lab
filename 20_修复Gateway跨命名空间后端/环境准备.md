# 环境准备 · 修复 Gateway API 跨命名空间后端

准备 kind v0.33.0 或更新版本、kubectl 和已启动的容器运行时。kind 自动选择 Docker、Podman 或 nerdctl。在仓库根目录进入本题目录，随后用下列命令创建集群。已有同名 kind 集群时可以跳过创建。

```sh
cd 20_修复Gateway跨命名空间后端
kind create cluster --name cka-gateway --config kind-config.yaml --wait 5m
```

本目录的 [kind-config.yaml](kind-config.yaml) 定义节点布局。还需要 Helm 和 curl。本题使用独立 kind 集群。

用 [setup.yaml](setup.yaml) 建立初始资源，再核对初始状态。

```sh
kubectl config use-context kind-cka-gateway
helm upgrade --install cka-gateway oci://docker.io/envoyproxy/gateway-helm --version v1.10.0 \
  --kube-context kind-cka-gateway -n envoy-gateway-system --create-namespace --wait --timeout 10m
kubectl wait --for=condition=Established crd/gatewayclasses.gateway.networking.k8s.io crd/gateways.gateway.networking.k8s.io crd/httproutes.gateway.networking.k8s.io crd/referencegrants.gateway.networking.k8s.io --timeout=90s
kubectl --context kind-cka-gateway apply -f setup.yaml
kubectl -n cka-20-backend rollout status deploy/reports --timeout=120s
envoy_labels=gateway.envoyproxy.io/owning-gateway-namespace=cka-20,gateway.envoyproxy.io/owning-gateway-name=edge
kubectl -n envoy-gateway-system wait --for=create deployment -l "$envoy_labels" --timeout=120s
kubectl -n envoy-gateway-system wait --for=condition=Available deployment -l "$envoy_labels" --timeout=10m
kubectl -n cka-20 get gateway,httproute
kubectl -n cka-20 describe httproute reports
kubectl -n envoy-gateway-system get pods
```

确认 HTTPRoute 已绑定 Gateway，且初始 ResolvedRefs 为 False。kind 中 LoadBalancer 可能没有外部 IP，Gateway 的 Programmed 条件可能仍为 False。验收使用端口转发。

重练时可以删除本题的独立集群 `kind delete cluster --name cka-gateway`，再重新创建。

如果 Helm 安装在 certgen Job 阶段超时，先用 `kubectl -n envoy-gateway-system get events --sort-by=.metadata.creationTimestamp` 检查镜像拉取事件。若集群节点下载缓慢，可在容器运行时准备事件中显示的镜像，再用 `kind load docker-image --name cka-gateway <镜像名>` 载入并重试安装。
