# 第 20 题 · 修复 Gateway API 跨命名空间后端

建议用时 20 分钟，环境准备完成后开始计时。

操作入口 `kubectl config use-context kind-cka-gateway`。Context 为 `kind-cka-gateway`，命名空间为 `cka-20`。

## 题目主干

修复 `cka-20/reports` HTTPRoute，使网关 `edge` 的主机 `reports.example.test` 能访问既有后端 `cka-20-backend/reports:80`。仅允许来自 `cka-20` 的 HTTPRoute 引用该名称的 Service。保留 Gateway、HTTPRoute 和 Service。

## 官方参考

- [Gateway API 跨命名空间路由](https://gateway-api.sigs.k8s.io/guides/user-guides/multiple-ns/) · 路由绑定和跨命名空间引用。
- [Envoy Gateway 安装](https://gateway.envoyproxy.io/v1.10/install/install-helm/) · 本地控制器及其 CRD。

## 验收标准

```sh
kubectl -n cka-20 describe httproute reports
kubectl -n envoy-gateway-system get svc \
  -l gateway.envoyproxy.io/owning-gateway-namespace=cka-20,gateway.envoyproxy.io/owning-gateway-name=edge
```

路由的 Accepted 与 ResolvedRefs 均为 True。将下列变量设为查到的 Envoy Service 名称，在一个终端运行第一条命令，在另一个终端运行 curl。

```sh
kubectl -n envoy-gateway-system port-forward svc/"$envoy_service" 18080:80
curl -fsS -H 'Host: reports.example.test' http://127.0.0.1:18080/
```

应返回 Nginx 首页。kind 中通过端口转发访问代理 Pod，无需分配 LoadBalancer 外部 IP。
