# 第 33 题 · 解题思路

## 关键技术难点

堆叠拓扑中一个节点停止会同时失去一个 API server 和一个 etcd 成员。剩余两个 etcd 成员仍可达到三成员集群的仲裁。只读请求可能不足以证明写入可用，题目用 ConfigMap 更新验证。

## 解题顺序与答案详解

先通过未停机的控制平面上的 etcd 容器检查成员。使用练习环境自带证书文件，不将其复制到主机。

```sh
kubectl --context kind-cka-ha -n kube-system exec etcd-cka-ha-control-plane -- \
  etcdctl --endpoints=https://127.0.0.1:2379 \
  --cacert=/etc/kubernetes/pki/etcd/ca.crt \
  --cert=/etc/kubernetes/pki/etcd/healthcheck-client.crt \
  --key=/etc/kubernetes/pki/etcd/healthcheck-client.key member list -w table
```

核对确有三个成员后再停止目标。在 HAProxy 健康检测收敛后执行写入，若遇短暂超时，确认只有目标容器停止后重试。

```sh
podman stop cka-ha-control-plane2
podman inspect --format '{{.State.Running}}' cka-ha-control-plane2
kubectl --context kind-cka-ha --request-timeout=10s -n cka-33 patch cm checkpoint --type=merge -p '{"data":{"phase":"failover-ok"}}'
kubectl --context kind-cka-ha --request-timeout=10s -n cka-33 get cm checkpoint -o jsonpath='{.data.phase}{"\n"}'
podman start cka-ha-control-plane2
kubectl --context kind-cka-ha wait --for=condition=Ready node/cka-ha-control-plane2 --timeout=180s
```

重新运行成员列表命令，应仍为三个原成员。如果停机阶段写入超时且不能尽快恢复，先把节点启动，再排查 HAProxy、剩余 API server 与 etcd 健康状态。

对照[题面验收标准](题目.md)检查最终状态。
