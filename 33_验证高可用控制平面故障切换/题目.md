# 第 33 题 · 验证高可用控制平面故障切换

建议用时 26 分钟，环境准备完成后开始计时。

操作入口 `kubectl config use-context kind-cka-ha`。Context 为 `kind-cka-ha`，命名空间为 `cka-33`。

## 题目主干

对独立 kind 集群执行一次单控制平面节点停机演练。先确认有 3 个控制平面与 3 个 etcd 成员。仅暂停目标控制平面 `cka-ha-control-plane2` 的节点服务（通过停止其 kind 节点容器），使用同一 kubeconfig API 入口，在该容器停止期间把 `checkpoint` ConfigMap 的 phase 改为 `failover-ok` 并读回。然后恢复该节点。保留 etcd 成员配置和负载均衡入口。

## 官方参考

- [Options for Highly Available Topology](https://kubernetes.io/docs/setup/production-environment/tools/kubeadm/ha-topology/) · 堆叠 etcd 和控制平面多数派。
- [kind Control-plane HA](https://kind.sigs.k8s.io/docs/user/quick-start/#control-plane-ha) · 独立多控制平面集群与本地入口。
- [etcd FAQ](https://etcd.io/docs/v3.7/faq/) · 集群成员数、仲裁和容错。

## 验收标准

```sh
kubectl --context kind-cka-ha get --raw=/readyz
kubectl --context kind-cka-ha get nodes
kubectl --context kind-cka-ha -n kube-system get pods -l component=etcd -o wide
kubectl --context kind-cka-ha -n kube-system logs etcd-cka-ha-control-plane2 --tail=5
kubectl --context kind-cka-ha -n cka-33 get cm checkpoint -o jsonpath='{.data.phase}{"\n"}'
```

需要提供目标节点容器停止期间成功写入并读回的证据。恢复后 4 个节点 Ready，三个 etcd Pod Ready，目标节点的 etcd 日志可读取，phase 为 failover-ok。
