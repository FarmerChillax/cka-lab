# 第 14 题：解题思路

## 关键技术难点

`minAvailable: 3` 要求三个副本始终可用，因此 eviction API 不允许驱逐任何 Pod。节点排空使用 eviction API，会遵守 PDB。应把约束改成 `maxUnavailable: 1`，随后再执行 drain。

## 答案详解

先确认阻塞原因：

```sh
kubectl -n cka-maint get pdb frontend
kubectl -n cka-maint get pods -o wide
kubectl drain cka-lab-worker2 --ignore-daemonsets --delete-emptydir-data
```

首次 drain 应报告违反 PDB。修改 PDB：

```sh
kubectl -n cka-maint patch pdb frontend --type=json \
  -p='[
    {"op":"remove","path":"/spec/minAvailable"},
    {"op":"add","path":"/spec/maxUnavailable","value":1}
  ]'
```

再次排空并等待 Deployment 恢复：

```sh
kubectl drain cka-lab-worker2 --ignore-daemonsets --delete-emptydir-data
kubectl -n cka-maint rollout status deployment/frontend
kubectl -n cka-maint get pods -l app=frontend -o wide
```

`drain` 会先 cordon 节点，再逐个驱逐受控制器管理的 Pod。软节点亲和性在目标节点不可调度时不会阻止 Pod 落到另一工作节点。题目要求保持维护状态，因此不要执行 `uncordon`。
