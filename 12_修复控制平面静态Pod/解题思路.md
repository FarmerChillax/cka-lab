# 第 12 题：解题思路与答案详解

## 关键技术难点

1. 静态 Pod 由 kubelet 直接读取主机文件管理；删除镜像 Pod 或编辑 API 对象都不能修复源清单。
2. 静态 Pod 不能引用 ConfigMap、Secret、ServiceAccount 等 API 对象，故障清单中的 ConfigMap 卷会被 kubelet 拒绝。
3. `kubectl debug node` 把节点根文件系统挂载到 `/host`；需要写主机文件时使用 `--profile=sysadmin`。

## 解题思路

先从 API 侧确认目标 Pod 缺失，再进入节点调试容器，查看 `/host/etc/kubernetes/manifests` 与 kubelet日志。删除静态 Pod 不支持的 API 对象引用，保存后由 kubelet自动重读文件并创建镜像 Pod。

## 答案详解

```sh
kubectl get node cka-lab-control-plane
kubectl -n kube-system get pod -l app=cka-node-web
kubectl debug node/cka-lab-control-plane -it --profile=sysadmin --image=busybox:1.36 -- sh
```

在调试 shell 中：

```sh
cat /host/etc/kubernetes/manifests/cka-node-web.yaml
vi /host/etc/kubernetes/manifests/cka-node-web.yaml
```

把 `volumeMounts` 和 `volumes` 两段全部删除，保留以下内容：

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: cka-node-web
  namespace: kube-system
  labels:
    app: cka-node-web
spec:
  containers:
  - name: web
    image: nginx:1.27.5
    ports:
    - containerPort: 80
```

保存后退出调试 shell，等待 kubelet 重新读取清单：

```sh
kubectl -n kube-system get pod -l app=cka-node-web -w
```

Pod Ready 后运行题面验收命令。若镜像 Pod 仍未出现，可重新进入节点查看文件缩进，并检查 `/host/var/log`；kind 的 kubelet日志位置可能随节点镜像变化，因此也可通过节点容器的 systemd journal 排查，但本题不要求使用特定容器运行时命令。
