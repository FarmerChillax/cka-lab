# 环境准备：修复控制平面静态 Pod

需要 `kind` v0.33.0 或更新版本、`kubectl` 和已启动的 kind 兼容容器运行时。本题沿用 `cka-lab` 集群；已有集群时跳过创建。

```sh
cd 12_修复控制平面静态Pod
kind create cluster --name cka-lab --config kind-config.yaml --wait 5m  # 仅在集群不存在时执行
kubectl config use-context kind-cka-lab
kubectl apply -f setup.yaml
kubectl -n kube-system wait --for=condition=Complete job/static-web-seed --timeout=120s
kubectl -n kube-system wait --for=condition=Ready pod/static-web-probe --timeout=120s
```

`setup.yaml` 通过一次性 Job 把故障清单写入 control-plane 节点的 `/etc/kubernetes/manifests/cka-node-web.yaml`，不依赖 Docker 或 Podman 专用的 `exec` 命令。准备阶段不要修改该主机文件。

确认 control-plane 节点 Ready，但目标镜像 Pod 没有正常出现，然后开始 24 分钟计时：

```sh
kubectl get node cka-lab-control-plane
kubectl -n kube-system get pod -l app=cka-node-web -o wide
kubectl -n kube-system get endpointslice -l kubernetes.io/service-name=cka-node-web
```

重练时先用 [cleanup.yaml](cleanup.yaml) 删除节点上的旧清单，再重建故障环境：

```sh
kubectl -n kube-system delete job static-web-cleanup --ignore-not-found
kubectl apply -f cleanup.yaml
kubectl -n kube-system wait --for=condition=Complete job/static-web-cleanup --timeout=120s
kubectl delete -f setup.yaml --ignore-not-found
kubectl delete -f cleanup.yaml --ignore-not-found
kubectl apply -f setup.yaml
kubectl -n kube-system wait --for=condition=Complete job/static-web-seed --timeout=120s
```
