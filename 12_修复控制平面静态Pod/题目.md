# 第 12 题：修复控制平面静态 Pod

**建议用时：** 24 分钟。**Context：** `kind-cka-lab`。**目标节点：** `cka-lab-control-plane`。

**操作入口：** `kubectl config use-context kind-cka-lab`

## 题目主干

control-plane 节点的 kubelet 应从 `/etc/kubernetes/manifests/cka-node-web.yaml` 启动静态 Pod `cka-node-web`，但 API 中没有可用的镜像 Pod，`Service/kube-system/cka-node-web` 也没有可用后端。

在不能通过容器运行时专用命令进入 kind 节点的前提下，使用 `kubectl debug node` 检查节点文件系统和 kubelet 管理的静态 Pod 配置。修复主机上的原文件，使其满足：

- 保持静态 Pod，而不是改成 Deployment、DaemonSet 或普通 API Pod。
- 名称、命名空间、标签、镜像和端口保持不变。
- 清单不得引用 ConfigMap、Secret、ServiceAccount 或其他 API 对象。
- 最终镜像 Pod Ready，带有 `kubernetes.io/config.mirror` 注解，并能通过现有 Service 返回 NGINX 首页。

官方参考：[Static Pods](https://kubernetes.io/docs/concepts/workloads/pods/static-pods/) 与 [Debugging Kubernetes Nodes With Kubectl](https://kubernetes.io/docs/tasks/debug/debug-cluster/kubectl-node-debug/)。

## 验收标准

```sh
kubectl -n kube-system wait --for=condition=Ready pod -l app=cka-node-web --timeout=120s
POD=$(kubectl -n kube-system get pod -l app=cka-node-web -o jsonpath='{.items[0].metadata.name}')
kubectl -n kube-system get pod "$POD" -o jsonpath='{.metadata.annotations.kubernetes\.io/config\.mirror}{"\n"}'
kubectl -n kube-system get pod "$POD" -o jsonpath='{.spec.nodeName}{"\n"}'
kubectl -n kube-system exec static-web-probe -- wget -qO- http://cka-node-web | head
```

镜像注解值应为非空，节点名应为 `cka-lab-control-plane`，最后一条命令应返回 NGINX 欢迎页。
