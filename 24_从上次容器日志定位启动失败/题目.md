# 第 24 题 · 从上次容器日志定位启动失败

建议用时 17 分钟，环境准备完成后开始计时。

操作入口 `kubectl config use-context kind-cka-next`。Context 为 `kind-cka-next`，命名空间为 `cka-24`。

## 题目主干

Deployment `reporter` 中的业务容器反复重启，同 Pod 的 `heartbeat` 仍在运行。查出业务容器上一次退出的原因，将日志和退出码分别保存到当前目录的 `reporter.previous.log` 与 `reporter.exit-code`。恢复应用，只允许调整 `settings` 中的配置和触发 rollout。保留容器命令及 ConfigMap 引用。

## 官方参考

- [Debug Running Pods](https://kubernetes.io/docs/tasks/debug/debug-application/debug-running-pod/) · 指定容器与读取上一次实例的日志。
- [ConfigMaps](https://kubernetes.io/docs/concepts/configuration/configmap/) · 环境变量从 ConfigMap 取值的行为。

## 验收标准

```sh
cat reporter.previous.log reporter.exit-code
kubectl -n cka-24 get deploy reporter
kubectl -n cka-24 logs deploy/reporter -c reporter
```

日志文件含具体配置错误，退出码文件为 64。Deployment 显示 1/1，当前业务日志含 reporter ready。
