# 第 18 题：解题思路

## 关键技术难点

etcd endpoint 启用了双向 TLS，必须同时提供 CA、客户端证书和私钥。kind 的 etcd 静态 Pod 已包含 `etcdctl`、`etcdutl` 及证书目录，因此可以通过 `kubectl exec` 完成练习。恢复目标必须是新的空目录，不能覆盖活动数据目录。

## 答案详解

获取 Pod 名称并检查证书路径：

```sh
ETCD_POD=$(kubectl -n kube-system get pod -l component=etcd \
  -o jsonpath='{.items[0].metadata.name}')
kubectl -n kube-system exec "$ETCD_POD" -- \
  ls /etc/kubernetes/pki/etcd
```

保存快照：

```sh
kubectl -n kube-system exec "$ETCD_POD" -- sh -c '
  ETCDCTL_API=3 etcdctl snapshot save /var/lib/etcd/cka-snapshot.db \
    --endpoints=https://127.0.0.1:2379 \
    --cacert=/etc/kubernetes/pki/etcd/ca.crt \
    --cert=/etc/kubernetes/pki/etcd/server.crt \
    --key=/etc/kubernetes/pki/etcd/server.key
'
```

检查快照并离线恢复：

```sh
kubectl -n kube-system exec "$ETCD_POD" -- \
  etcdutl snapshot status /var/lib/etcd/cka-snapshot.db -w table

kubectl -n kube-system exec "$ETCD_POD" -- \
  etcdutl snapshot restore /var/lib/etcd/cka-snapshot.db \
    --data-dir=/var/lib/etcd/cka-restore
```

最后确认恢复目录及 API：

```sh
kubectl -n kube-system exec "$ETCD_POD" -- \
  test -f /var/lib/etcd/cka-restore/member/snap/db
kubectl get --raw=/readyz
kubectl -n cka-etcd get configmap checkpoint
```

本题只验证恢复产物，不将静态 Pod 指向新目录。这样可以练习备份与恢复命令，同时保持当前练习集群在线。
