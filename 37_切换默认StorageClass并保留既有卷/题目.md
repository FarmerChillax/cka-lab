# 第 37 题 · 切换默认 StorageClass 并保留既有卷

建议用时 24 分钟。准备完成后开始计时。

操作入口 `kubectl config use-context kind-cka-storage37`，命名空间 `cka-37`。

## 题目主干

把默认 StorageClass 从 `standard` 切换为既有的 `standard-next`，最终只保留一个默认类。保留旧类和已绑定的 `existing` PVC 及数据。保留显式不使用类的 `static-only` PVC。创建不写 storageClassName 的 `fresh` PVC，容量 64Mi、ReadWriteOnce，并用 BusyBox Pod `fresh-reader` 挂载到 `/data` 触发供应。

## 官方参考

- [Change the default StorageClass](https://kubernetes.io/docs/tasks/administer-cluster/change-default-storage-class/) · 默认类注解和迁移顺序。
- [Storage Classes](https://kubernetes.io/docs/concepts/storage/storage-classes/#default-storageclass) · 省略 storageClassName 与空字符串的区别。

## 验收标准

```sh
kubectl get storageclass
kubectl -n cka-37 get pvc existing static-only fresh
kubectl -n cka-37 exec old-reader -- cat /data/marker
kubectl -n cka-37 exec fresh-reader -- sh -ec 'echo fresh-ok > /data/probe; cat /data/probe'
```

只有 `standard-next` 显示为 default。existing 仍 Bound 到 standard，读取 `before-switch`。static-only 的类为空且仍 Pending，fresh 绑定到 standard-next 并可写入。
