# 第 3 题：解题思路

## 关键技术难点

1. toleration 允许 Pod 使用带污点节点，但不保证它一定被调度到该节点；必须另设强制节点亲和性。
2. `completions: 3` 是成功执行总次数，`parallelism: 2` 是最多同时运行的 Pod 数，二者不能混淆。
3. 每次执行需输出独立序号，适合使用 Indexed Job 提供的 `JOB_COMPLETION_INDEX`。
4. Job Pod 的 `restartPolicy` 只能使用 `Never` 或 `OnFailure`。

## 排查与实施顺序

1. 确认专用节点 Ready，并核对 `workload=batch` 标签和 `dedicated=batch:NoSchedule` 污点。
2. 在 Job Pod 模板中同时配置强制节点亲和性和对应 toleration。
3. 使用 Indexed Job，设置成功次数 3、最大并发数 2，并在容器命令中输出完成序号。
4. 创建 Job，等待 Complete，再核对每个 Pod 的节点和日志。如 Pod Pending，先查看 Pod 调度事件。

## 答案详解

### 参考清单

```yaml
apiVersion: batch/v1
kind: Job
metadata:
  name: batch-report
  namespace: cka-lab
spec:
  completionMode: Indexed
  completions: 3
  parallelism: 2
  template:
    spec:
      restartPolicy: Never
      affinity:
        nodeAffinity:
          requiredDuringSchedulingIgnoredDuringExecution:
            nodeSelectorTerms:
            - matchExpressions:
              - key: workload
                operator: In
                values: ["batch"]
      tolerations:
      - key: dedicated
        operator: Equal
        value: batch
        effect: NoSchedule
      containers:
      - name: report
        image: busybox:1.36
        command: ["/bin/sh", "-c"]
        args: ["echo index=$JOB_COMPLETION_INDEX"]
```

保存为 `batch-report.yaml` 后执行 `kubectl apply -f batch-report.yaml`。

节点亲和性负责强制选中专用节点，toleration 负责允许 Pod 通过该节点的污点检查。Indexed Job 提供 `JOB_COMPLETION_INDEX`，`completions` 与 `parallelism` 分别控制成功次数和最大并发数。
