# 第 3 题：将批处理任务固定到专用节点

**建议用时：** 13 分钟。**操作 context：** `kind-cka-lab`。**命名空间：** `cka-lab`。

**操作入口：** `kubectl config use-context kind-cka-lab`

## 题目主干

创建名为 `batch-report` 的 Job，使用 `busybox:1.36`。要求完成 **3 次成功执行**，最多同时运行 **2 个 Pod**；每个 Pod 输出自己的完成序号。

所有 Job Pod 都必须调度到具有 `workload=batch` 标签、带有 `dedicated=batch:NoSchedule` 污点的专用节点。Job 最终须达到 Complete 状态。

## 题面引用信息

### 关键参数

| 项目 | 题面给定值 |
| --- | --- |
| Kubernetes context | `kind-cka-lab` |
| Namespace / Job | `cka-lab` / `batch-report` |
| 容器镜像 | `busybox:1.36` |
| 成功执行总次数 / 最大并发数 | 3 / 2 |
| 专用节点标签 | `workload=batch` |
| 专用节点污点 | `dedicated=batch:NoSchedule` |
| 输出 | 每次执行的完成序号 |

### 官方参考链接

1. [Jobs](https://kubernetes.io/docs/concepts/workloads/controllers/job/)：定位 **Parallel execution for Jobs** 和 **Completion mode**；查看 `spec.completions`、`spec.parallelism`、`completionMode` 与完成序号环境变量。
2. [Assigning Pods to Nodes](https://kubernetes.io/docs/concepts/scheduling-eviction/assign-pod-node/)：定位 **Node affinity**；查看强制调度约束的配置位置。
3. [Taints and Tolerations](https://kubernetes.io/docs/concepts/scheduling-eviction/taint-and-toleration/)：查看 `NoSchedule` 与 Pod toleration 的写法。

## 验收标准

```sh
kubectl -n cka-lab wait --for=condition=complete \
  job/batch-report --timeout=120s
kubectl -n cka-lab get job batch-report
kubectl -n cka-lab get pods \
  -l batch.kubernetes.io/job-name=batch-report -o wide
```

预期 Job 达到 `3/3` 次完成，三个已完成 Pod 的 `NODE` 均为 `cka-lab-worker2`。逐个运行 `kubectl -n cka-lab logs <Pod名称>`，应能看到 `index=0`、`index=1`、`index=2`。如 Pod Pending，使用 `kubectl -n cka-lab describe pod <Pod名称>` 查看调度事件。
