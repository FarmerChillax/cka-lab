# 环境准备：使用 Kustomize 部署组件

需要已启动的 Podman、`kubectl` 和 `kind` v0.33.0 或更新版本。本题沿用 `cka-lab` 集群；已有集群时跳过创建。macOS 上如 Podman 虚拟机未运行，先执行 `podman machine start`。

在仓库根目录进入本题目录。kind 配置已保存为 [kind-config.yaml](kind-config.yaml)：

```sh
cd 05_使用Kustomize部署组件
```

仅在集群不存在时运行：

```sh
podman info
kind version
KIND_EXPERIMENTAL_PROVIDER=podman kind create cluster \
  --name cka-lab --config kind-config.yaml --wait 5m
```

切换 context，应用 [setup.yaml](setup.yaml) 创建命名空间。题目提供的初始 Kustomize 配置已保存于 [fixtures/base](fixtures/base/kustomization.yaml) 和 [fixtures/overlay](fixtures/overlay/kustomization.yaml)；复制到本机临时目录后作答，不修改仓库中的原件：

```sh
kubectl config use-context kind-cka-lab
kubectl get nodes
kubectl apply -f setup.yaml
mkdir -p /tmp/cka-q05/base /tmp/cka-q05/overlay
cp fixtures/base/*.yaml /tmp/cka-q05/base/
cp fixtures/overlay/kustomization.yaml /tmp/cka-q05/overlay/
```

确认 `kubectl kustomize /tmp/cka-q05/base` 能输出 Deployment 和 Service，且 `kubectl -n cka-components get deployment portal` 显示 NotFound。开始本题的 18 分钟计时。**不要在准备阶段应用 base 或 overlay**：初始 overlay 尚未生成 Deployment 所引用的 ConfigMap。

重练时先确认 context，再删除本题资源并从仓库配置文件恢复初始 base 和 overlay；无需删除共用集群。

```sh
kubectl config current-context
kubectl -n cka-components delete deployment portal --ignore-not-found
kubectl -n cka-components delete service portal --ignore-not-found
kubectl -n cka-components delete configmap -l app=cka-q05 --ignore-not-found
cp fixtures/base/*.yaml /tmp/cka-q05/base/
cp fixtures/overlay/kustomization.yaml /tmp/cka-q05/overlay/
```
