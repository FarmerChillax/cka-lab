# 第 5 题：解题思路与答案详解

## 关键技术难点

1. base 是共享原始配置，overlay 应组合 base 并声明环境差异；直接 `kubectl set image` 无法满足可重复构建要求。
2. `configMapGenerator` 默认给名称增加内容哈希。Kustomize 会把 Deployment 中已知的 ConfigMap 引用更新为生成后的名称。
3. `namespace`、`images`、`replicas` 与生成器作用于构建结果；先用 `kubectl kustomize` 检查，再 `kubectl apply -k`。

## 解题思路

阅读 base 中的对象名、镜像及 ConfigMap 引用。只编辑 overlay 的 `kustomization.yaml`，生成预览，确认副本数、镜像、命名空间与引用，然后应用并检查 Pod 环境变量。

## 答案详解

把 `/tmp/cka-q05/overlay/kustomization.yaml` 改为：

```yaml
resources:
- ../base
namespace: cka-components
images:
- name: nginx
  newTag: 1.27.5
replicas:
- name: portal
  count: 3
configMapGenerator:
- name: portal-settings
  literals:
  - APP_MODE=practice
  options:
    labels:
      app: cka-q05
```

先查看输出，再应用：

```sh
kubectl kustomize /tmp/cka-q05/overlay
kubectl apply -k /tmp/cka-q05/overlay
kubectl -n cka-components rollout status deployment/portal
kubectl -n cka-components get deployment portal
kubectl -n cka-components get pods -l app=portal
kubectl -n cka-components get service portal
kubectl -n cka-components get endpointslice -l kubernetes.io/service-name=portal
kubectl -n cka-components exec deployment/portal -- printenv APP_MODE
```

构建输出中的 ConfigMap 名称会是 `portal-settings-<哈希>`，Deployment 的 `envFrom.configMapRef.name` 应指向它。集群中 Deployment 应显示 `3/3`，最后一条命令输出 `practice`。若 Pod 报 `CreateContainerConfigError`，先检查构建输出中的 ConfigMap 引用和实际创建的 ConfigMap 名称；若 Service 无后端，核对 base 中 Service selector 与 Pod 标签。

## 本次答题结果

**答题日期：** 2026-11-11

**判定：** 部分正确，集群运行状态符合要求，但 Kustomize 构建结果未满足全部条件。

以下记录依据 `/tmp/cka-q05` 中的实际配置、`kubectl kustomize` 原始输出和答题完成后的集群状态整理：

1. `/tmp/cka-q05/base` 与题目提供的原始 base 完全一致，作答只修改了 overlay，符合操作限制。
2. overlay 将 `portal` 副本数设置为 3，并把 `nginx` 镜像标签更新为 `1.27.5`。
3. 通过 `configMapGenerator` 和 overlay 中的 `.env` 文件生成 `APP_MODE=practice`，未关闭名称哈希后缀。构建结果中的 ConfigMap 为 `portal-settings-d98gf4f264`，Deployment 的 `envFrom.configMapRef.name` 也正确引用该名称。
4. 实际 Deployment 已成功滚动更新，副本数为 3，镜像为 `nginx:1.27.5`，Ready 副本数为 3。
5. 三个 Pod 均为 `1/1 Running`，Service `portal` 保持存在；EndpointSlice 中的 `10.244.1.10`、`10.244.1.11` 和 `10.244.1.12` 三个后端均为 `ready: true`、`serving: true`。
6. 在 Deployment 的 Pod 中执行 `printenv APP_MODE`，实际输出 `practice`，配置已正确注入。
7. overlay 的 `kustomization.yaml` 缺少 `namespace: cka-components`。`kubectl kustomize /tmp/cka-q05/overlay` 的原始输出中，ConfigMap、Service 和 Deployment 的 `metadata.namespace` 均未设置。虽然实际资源已位于 `cka-components`，但不满足题面“构建结果应位于 `cka-components`”的要求。

本次作答正确实现了副本数、镜像、ConfigMapGenerator 哈希引用、环境变量注入、Service 和三个 Ready 后端，但仍需在 overlay 中补充 `namespace: cka-components`，使命名空间由 Kustomize 构建结果本身声明，而不是只依赖应用命令或当前 context 的命名空间。
