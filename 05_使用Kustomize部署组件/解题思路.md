# 第 5 题：解题思路与答案详解

## 关键技术难点

1. base 是共享原始配置，overlay 应组合 base 并声明环境差异；直接 `kubectl set image` 无法满足可重复构建要求。
2. `configMapGenerator` 默认给名称增加内容哈希。Kustomize 会把 Deployment 中已知的 ConfigMap 引用更新为生成后的名称。
3. `namespace`、`images`、`replicas` 与生成器作用于构建结果；先用 `kubectl kustomize` 检查，再 `kubectl apply -k`。

## 解题思路

阅读 base 中的对象名、镜像及 ConfigMap 引用。只编辑 overlay 的 `kustomization.yaml`，生成预览，确认副本数、镜像、命名空间与引用，然后应用并检查 Pod 环境变量。

## 答案详解

把 `/tmp/cka-q05/overlay/kustomization.yaml` 改为：

```yaml
resources:
- ../base
namespace: cka-components
images:
- name: nginx
  newTag: 1.27.5
replicas:
- name: portal
  count: 3
configMapGenerator:
- name: portal-settings
  literals:
  - APP_MODE=practice
  options:
    labels:
      app: cka-q05
```

先查看输出，再应用：

```sh
kubectl kustomize /tmp/cka-q05/overlay
kubectl apply -k /tmp/cka-q05/overlay
kubectl -n cka-components rollout status deployment/portal
kubectl -n cka-components get deployment portal
kubectl -n cka-components get pods -l app=portal
kubectl -n cka-components get service portal
kubectl -n cka-components get endpointslice -l kubernetes.io/service-name=portal
kubectl -n cka-components exec deployment/portal -- printenv APP_MODE
```

构建输出中的 ConfigMap 名称会是 `portal-settings-<哈希>`，Deployment 的 `envFrom.configMapRef.name` 应指向它。集群中 Deployment 应显示 `3/3`，最后一条命令输出 `practice`。若 Pod 报 `CreateContainerConfigError`，先检查构建输出中的 ConfigMap 引用和实际创建的 ConfigMap 名称；若 Service 无后端，核对 base 中 Service selector 与 Pod 标签。
