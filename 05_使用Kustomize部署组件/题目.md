# 第 5 题：使用 Kustomize 部署组件

**建议用时：** 18 分钟。**Context：** `kind-cka-lab`。**命名空间：** `cka-components`。

**操作入口：** `kubectl config use-context kind-cka-lab`

## 题目主干

本机 `/tmp/cka-q05/base` 已提供 `portal` Deployment 和 Service；`/tmp/cka-q05/overlay` 只有初始引用。**仅修改 overlay**，不要改动 base。使用 Kustomize 将组件部署到 `cka-components`，满足以下要求：

1. Deployment 为 **3 个副本**，容器镜像为 `nginx:1.27.5`。
2. 通过 Kustomize 生成名为 `portal-settings` 的 ConfigMap，键 `APP_MODE` 的值为 `practice`。Deployment 已通过 `envFrom` 引用该配置；最终 Pod 中须能读取该环境变量。
3. 保留 `portal` Service，且其后端为 3 个 Ready Pod。

不得直接修改集群中的 Deployment 来代替 overlay，也不得关闭 ConfigMap 生成名称的哈希后缀。

## 题面引用信息

| 项目 | 给定值 |
| --- | --- |
| Base / overlay | `/tmp/cka-q05/base` / `/tmp/cka-q05/overlay` |
| Namespace | `cka-components` |
| Deployment / Service | `portal` / `portal` |
| 副本数 / 镜像 | 3 / `nginx:1.27.5` |
| 配置 | `portal-settings` 中 `APP_MODE=practice` |

官方配置参考：[Kustomize](https://kubernetes.io/docs/tasks/manage-kubernetes-objects/kustomization/) 中的 **Bases and Overlays**、**Images**、**Replicas**、**ConfigMapGenerator** 和 `kubectl apply -k`。

## 验收标准

```sh
kubectl kustomize /tmp/cka-q05/overlay
kubectl -n cka-components rollout status deployment/portal
kubectl -n cka-components get deployment portal
kubectl -n cka-components get pods -l app=portal
kubectl -n cka-components get service portal
kubectl -n cka-components get endpointslice -l kubernetes.io/service-name=portal
kubectl -n cka-components exec deployment/portal -- printenv APP_MODE
```

构建结果应位于 `cka-components`，包含带哈希后缀的 ConfigMap，Deployment 对它的引用应随之更新。Deployment 应为 `3/3`，三个 Pod Ready，EndpointSlice 应有三个可用后端；最后一条命令应输出 `practice`。
