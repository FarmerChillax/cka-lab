# 第 2 题：限定审计账号权限

**建议用时：** 10 分钟。**操作 context：** `kind-cka-lab`。**命名空间：** `cka-lab`。

**操作入口：** `kubectl config use-context kind-cka-lab`

## 题目主干

为现有 ServiceAccount `cka-lab/auditor` 配置权限，使其能够在 `cka-lab` 命名空间中：

1. `get`、`list`、`watch` Pods；
2. 读取 Pod 日志；
3. 仅读取名为 `runtime` 的 ConfigMap。

不得赋予写入权限，也不得将权限扩大到其他命名空间。完成后用命令验证允许和拒绝的操作。

## 题面引用信息

### 关键参数

| 项目 | 题面给定值 |
| --- | --- |
| Kubernetes context | `kind-cka-lab` |
| Namespace | `cka-lab` |
| 现有 ServiceAccount | `auditor` |
| 需要限定名称的 ConfigMap | `runtime` |
| Pod 操作 | `get`、`list`、`watch` |
| 日志操作 | 读取 Pod 日志 |
| 权限边界 | 不可写入，不可扩展到其他命名空间 |

### 官方参考链接

1. [Using RBAC Authorization](https://kubernetes.io/docs/reference/access-authn-authz/rbac/)：定位 **Role and ClusterRole**、**RoleBinding and ClusterRoleBinding**、**Referring to resources**；查看子资源 `pods/log` 和按名称限定资源的写法。
2. [`kubectl auth can-i`](https://kubernetes.io/docs/reference/kubectl/generated/kubectl_auth/kubectl_auth_can-i/)：查看 `--as`、`--subresource` 和 `TYPE/NAME` 的用法。

## 验收标准

以下命令模拟 `cka-lab/auditor`。前三项应输出 `yes`，后三项应输出 `no`：

```sh
SA=system:serviceaccount:cka-lab:auditor
kubectl auth can-i list pods -n cka-lab --as="$SA"
kubectl auth can-i get pods --subresource=log -n cka-lab --as="$SA"
kubectl auth can-i get configmaps/runtime -n cka-lab --as="$SA"
kubectl auth can-i get configmaps/other -n cka-lab --as="$SA"
kubectl auth can-i delete pods -n cka-lab --as="$SA"
kubectl auth can-i list pods -n default --as="$SA"
```

还可检查 `get`、`watch` Pods 均为 `yes`，以及 `list` ConfigMaps 为 `no`。不得创建 ClusterRoleBinding 或授予写入动词。
