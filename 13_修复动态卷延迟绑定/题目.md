# 第 13 题：修复动态卷延迟绑定

**建议用时：** 24 分钟。**Context：** `kind-cka-lab`。**命名空间：** `cka-dynamic-storage`。

**操作入口：** `kubectl config use-context kind-cka-lab`

## 题目主干

`StatefulSet/ledger` 必须运行在带有标签 `cka.storage/profile=fast` 的节点上，但其动态卷配置无法可靠地在调度决策后完成本地卷制备。

修复存储与工作负载，满足以下要求：

- 保留 kind 自带的 `StorageClass/standard`，不得修改或删除它。
- 新建 `StorageClass/local-retain-wait`，provisioner 为 `rancher.io/local-path`，`reclaimPolicy` 为 `Retain`，`volumeBindingMode` 为 `WaitForFirstConsumer`；不要把它设为默认类。
- 让 `StatefulSet/ledger` 的 `data` claim template 使用新 StorageClass，申请 `100Mi`、`ReadWriteOnce`。保留 StatefulSet 名称、Service、容器、挂载路径和 `cka.storage/profile=fast` 节点选择条件。
- 可以删除尚未承载有效数据的初始 PVC；不得手工创建 PV，也不得用 `spec.nodeName` 绕过调度器。
- Pod Ready 后写入 `/data/ledger.log` 内容 `cka-storage-ok`，删除 Pod 让 StatefulSet 重建，并确认内容仍存在。

官方参考：[Storage Classes](https://kubernetes.io/docs/concepts/storage/storage-classes/) 的 `WaitForFirstConsumer` 与 [Dynamic Volume Provisioning](https://kubernetes.io/docs/concepts/storage/dynamic-provisioning/)。

## 验收标准

```sh
kubectl -n cka-dynamic-storage rollout status statefulset/ledger --timeout=180s
kubectl -n cka-dynamic-storage get pod ledger-0 -o wide
kubectl -n cka-dynamic-storage get pvc data-ledger-0
PV=$(kubectl -n cka-dynamic-storage get pvc data-ledger-0 -o jsonpath='{.spec.volumeName}')
kubectl get pv "$PV" -o jsonpath='{.spec.persistentVolumeReclaimPolicy}{" "}{.spec.nodeAffinity.required.nodeSelectorTerms[0].matchExpressions[0].values[0]}{"\n"}'
kubectl get sc local-retain-wait -o jsonpath='{.volumeBindingMode}{" "}{.reclaimPolicy}{"\n"}'
kubectl -n cka-dynamic-storage exec ledger-0 -- cat /data/ledger.log
```

Pod 应位于 fast 节点，PVC 为 Bound，PV 回收策略为 Retain，StorageClass 输出 `WaitForFirstConsumer Retain`，文件内容包含 `cka-storage-ok`。
