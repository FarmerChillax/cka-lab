# 第 13 题：解题思路与答案详解

## 关键技术难点

1. `Immediate` 会在调度前尝试制备或绑定卷，不适合受节点拓扑约束的本地存储；`WaitForFirstConsumer` 会把 Pod 调度条件纳入选择。
2. StorageClass 的关键制备属性不能按题意原地改造，StatefulSet 的 claim template 也不能直接修改，因此需要新建 StorageClass 并重建未使用的 claim。
3. `Retain` 是 PV 的回收策略；它与 Pod 重建期间 PVC 对同一卷的持续引用是两层不同的持久性语义。

## 解题思路

先从 PVC events、StorageClass 和 Pod 调度条件定位绑定模式冲突。创建新 StorageClass 后删除旧 StatefulSet 和无有效数据的 PVC，再用新 claim template 重建。最后通过写文件、删除 Pod、读取文件验证持久性。

## 答案详解

保存并应用 `local-retain-wait.yaml`：

```yaml
apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata:
  name: local-retain-wait
provisioner: rancher.io/local-path
reclaimPolicy: Retain
volumeBindingMode: WaitForFirstConsumer
```

删除尚无有效数据的初始 StatefulSet 和 PVC：

```sh
kubectl apply -f local-retain-wait.yaml
kubectl -n cka-dynamic-storage delete statefulset ledger
kubectl -n cka-dynamic-storage delete pvc data-ledger-0 --ignore-not-found
```

将 `setup.yaml` 中的 StatefulSet 部分复制为临时文件，把 `volumeClaimTemplates` 中的 `storageClassName` 改为 `local-retain-wait` 后应用；也可使用以下完整关键部分核对：

```yaml
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: ledger
  namespace: cka-dynamic-storage
spec:
  serviceName: ledger
  replicas: 1
  selector:
    matchLabels: {app: ledger}
  template:
    metadata:
      labels: {app: ledger}
    spec:
      nodeSelector:
        cka.storage/profile: fast
      containers:
      - name: ledger
        image: busybox:1.36
        command: ["sh", "-c", "touch /data/ledger.log; tail -f /data/ledger.log"]
        volumeMounts:
        - name: data
          mountPath: /data
  volumeClaimTemplates:
  - metadata:
      name: data
    spec:
      accessModes: ["ReadWriteOnce"]
      storageClassName: local-retain-wait
      resources:
        requests:
          storage: 100Mi
```

```sh
kubectl apply -f ledger-fixed.yaml
kubectl -n cka-dynamic-storage rollout status statefulset/ledger --timeout=180s
kubectl -n cka-dynamic-storage exec ledger-0 -- sh -c 'echo cka-storage-ok >> /data/ledger.log'
kubectl -n cka-dynamic-storage delete pod ledger-0
kubectl -n cka-dynamic-storage wait --for=condition=Ready pod/ledger-0 --timeout=180s
kubectl -n cka-dynamic-storage exec ledger-0 -- cat /data/ledger.log
```

若 PVC 仍为 Pending，查看 PVC events，并确认 Pod 使用 `nodeSelector` 而不是 `nodeName`；若 PV 的节点亲和性不是 fast 节点，确认旧 PVC 已删除且新 PVC 的 StorageClass 名正确。
