# 环境准备：修复动态卷延迟绑定

需要 `kind` v0.33.0 或更新版本、`kubectl` 和已启动的 kind 兼容容器运行时。本题使用 kind 自带的 Local Path Provisioner，沿用 `cka-lab` 集群；已有集群时跳过创建。

```sh
cd 13_修复动态卷延迟绑定
kind create cluster --name cka-lab --config kind-config.yaml --wait 5m  # 仅在集群不存在时执行
kubectl config use-context kind-cka-lab
kubectl label node cka-lab-worker cka.storage/profile=general --overwrite
kubectl label node cka-lab-worker2 cka.storage/profile=fast --overwrite
kubectl -n local-path-storage rollout status deployment/local-path-provisioner --timeout=120s
kubectl apply -f setup.yaml
```

集群配置见 [kind-config.yaml](kind-config.yaml)，初始故障资源见 [setup.yaml](setup.yaml)。等待约 30 秒后确认 PVC 或 Pod 没有正常进入可用状态，再开始 24 分钟计时：

```sh
kubectl -n cka-dynamic-storage get pod,pvc
kubectl -n cka-dynamic-storage describe pvc data-ledger-0
kubectl get sc local-immediate standard
```

`local-immediate` 故意使用不适合该拓扑受限工作负载的绑定模式。重练时删除本题资源并重新应用初始配置；不要删除 kind 自带的 `standard` StorageClass：

```sh
PV=$(kubectl -n cka-dynamic-storage get pvc data-ledger-0 -o jsonpath='{.spec.volumeName}' 2>/dev/null || true)
kubectl delete namespace cka-dynamic-storage --ignore-not-found --wait=true
[ -z "$PV" ] || kubectl delete pv "$PV" --ignore-not-found
kubectl delete sc local-immediate local-retain-wait --ignore-not-found
kubectl apply -f setup.yaml
```

删除 PV 仅用于清理本题 `Retain` 策略留下的练习卷；变量为空时不会执行删除。
