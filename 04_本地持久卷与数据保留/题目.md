# 第 4 题：本地持久卷与数据保留

**建议用时：** 15 分钟。**Context：** `kind-cka-lab`。**命名空间：** `cka-storage`。

**操作入口：** `kubectl config use-context kind-cka-lab`

## 题目主干

`cka-lab-worker` 节点已有目录 `/var/local/cka-archive`。请创建静态本地 PersistentVolume `archive-pv`，容量 **1Gi**，访问模式 **ReadWriteOnce**，回收策略 **Retain**，仅允许在该节点使用。创建 PVC `cka-storage/archive-claim`，请求 **512Mi**，并确保它绑定到该 PV。不要使用集群默认 StorageClass 或动态供给。

创建名为 `archive-check`、镜像为 `busybox:1.36` 的 Pod，将 PVC 挂载到 `/data`，保持 Pod 运行。写入 `/data/check.txt`，内容为 `cka-archive-ok`。删除并重新创建该 Pod 后，文件内容仍须可读。不得删除 PV 或 PVC 来完成数据验证。

## 题面引用信息

| 项目 | 给定值 |
| --- | --- |
| PV / PVC | `archive-pv` / `cka-storage/archive-claim` |
| 节点 / 本地路径 | `cka-lab-worker` / `/var/local/cka-archive` |
| PV 容量 / PVC 请求 | 1Gi / 512Mi |
| 访问模式 / 回收策略 | ReadWriteOnce / Retain |
| Pod / 挂载路径 | `archive-check` / `/data` |

官方配置参考：[Persistent Volumes](https://kubernetes.io/docs/concepts/storage/persistent-volumes/)（**Persistent Volumes**、**Claims As Volumes**、**Node Affinity**）和 [local 卷](https://kubernetes.io/docs/concepts/storage/volumes/#local)（`local.path` 与节点亲和性）。

## 验收标准

```sh
kubectl get pv archive-pv
kubectl -n cka-storage get pvc archive-claim
kubectl -n cka-storage get pod archive-check -o wide
kubectl -n cka-storage exec archive-check -- cat /data/check.txt
```

PV/PVC 应为 `Bound`；Pod 应为 `Running` 且位于 `cka-lab-worker`；最后一条命令应输出 `cka-archive-ok`。删除并重新创建 Pod 后再次执行最后一条命令，结果仍应相同。
