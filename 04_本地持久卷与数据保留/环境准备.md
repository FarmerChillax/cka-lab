# 环境准备：本地持久卷与数据保留

需要已启动的 Podman、`kubectl` 和 `kind` v0.33.0 或更新版本。macOS 上如 Podman 虚拟机未运行，先执行 `podman machine start`。本题沿用前几题的 `cka-lab` 集群；已有集群时跳过创建。

在仓库根目录进入本题目录。kind 配置已保存为 [kind-config.yaml](kind-config.yaml)：

```sh
cd 04_本地持久卷与数据保留
```

仅在集群不存在时运行：

```sh
podman info
kind version
KIND_EXPERIMENTAL_PROVIDER=podman kind create cluster \
  --name cka-lab --config kind-config.yaml --wait 5m
```

应用 [setup.yaml](setup.yaml) 创建命名空间，再准备本题的数据目录。此路径位于 **kind worker 节点容器内**，不是 macOS 主机上的同名路径：

```sh
kubectl config use-context kind-cka-lab
kubectl get nodes
kubectl apply -f setup.yaml
podman exec cka-lab-worker mkdir -p /var/local/cka-archive
kubectl get node cka-lab-worker -o jsonpath='{.metadata.labels.kubernetes\.io/hostname}{"\n"}'
```

最后一条命令应输出 `cka-lab-worker`。此时不要创建 PV、PVC 或业务 Pod。开始本题的 15 分钟计时。

重练时，只在练习集群中删除此前创建的 `archive-check` Pod、`archive-claim` PVC 和 `archive-pv` PV，再清理节点目录内容。先确认 context，避免误删其他集群资源：

```sh
kubectl config current-context
kubectl -n cka-storage delete pod archive-check --ignore-not-found
kubectl -n cka-storage delete pvc archive-claim --ignore-not-found
kubectl delete pv archive-pv --ignore-not-found
podman exec cka-lab-worker sh -c 'rm -f /var/local/cka-archive/check.txt'
```
