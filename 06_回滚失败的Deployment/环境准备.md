# 环境准备：回滚失败的 Deployment

需要 `kind` v0.33.0 或更新版本、`kubectl` 和已启动的 kind 兼容容器运行时。kind 默认自动选择可用运行时。本题沿用 `cka-lab` 集群；已有集群时跳过创建。

从仓库根目录进入本题目录：

```sh
cd 06_回滚失败的Deployment
```

集群配置见 [kind-config.yaml](kind-config.yaml)。仅在集群不存在时执行：

```sh
kind create cluster --name cka-lab --config kind-config.yaml --wait 5m
```

先应用 [setup.yaml](setup.yaml)，等待初始版本稳定；再应用 [broken-rollout.yaml](broken-rollout.yaml) 制造待排查的失败更新。不要跳过首次等待，否则可能尚未留下可回滚的健康版本。

```sh
kubectl config use-context kind-cka-lab
kubectl get nodes
kubectl apply -f setup.yaml
kubectl -n cka-rollout rollout status deployment/release-web --timeout=120s
kubectl apply -f broken-rollout.yaml
kubectl -n cka-rollout get deployment,replicaset,pod
```

确认 `release-web` 有两个版本的 ReplicaSet，最新 Pod 未就绪后，开始本题的 15 分钟计时。不要在准备阶段修复更新。共用集群中的其他题目资源无需更改。

重练前先确认 context，再删除本题 Deployment 和 Service；随后重新执行上述两次应用及首次等待，建立新的版本历史：

```sh
kubectl config current-context
kubectl -n cka-rollout delete deployment release-web --ignore-not-found
kubectl -n cka-rollout delete service release-web --ignore-not-found
```
