# 第 6 题：解题思路与答案详解

## 关键技术难点

1. `maxUnavailable: 0` 会让旧版健康 Pod 保留；看到 Service 仍可访问，不表示新版本成功。
2. Deployment 版本历史存于 ReplicaSet；删除重建会丢失本题需要的回滚路径。
3. 回滚只恢复 Pod 模板中的上个版本，不应改变期望副本数或滚动更新策略。

## 解题思路

先查看 Deployment、ReplicaSet 和新 Pod 的事件，确认失败更新与旧版健康副本并存；再看 rollout history，执行 undo，等待当前版本稳定并核对镜像与 Service。

## 答案详解

```sh
kubectl -n cka-rollout get deployment,replicaset,pod -o wide
kubectl -n cka-rollout rollout history deployment/release-web
kubectl -n cka-rollout describe deployment release-web
kubectl -n cka-rollout describe pods -l app=release-web
```

新 Pod 使用不存在的 `nginx:cka-invalid-tag`，会出现镜像拉取失败；初始版本 `nginx:1.27.5` 的 ReplicaSet 仍保留。回滚到上一版本：

```sh
kubectl -n cka-rollout rollout undo deployment/release-web
kubectl -n cka-rollout rollout status deployment/release-web --timeout=120s
kubectl -n cka-rollout get deployment release-web
kubectl -n cka-rollout get pods -l app=release-web
kubectl -n cka-rollout get deployment release-web \
  -o jsonpath='{.spec.template.spec.containers[0].image}{"\n"}'
kubectl -n cka-rollout get deployment release-web \
  -o jsonpath='{.spec.replicas}{" "}{.spec.strategy.rollingUpdate.maxSurge}{" "}{.spec.strategy.rollingUpdate.maxUnavailable}{"\n"}'
```

预期镜像为 `nginx:1.27.5`，副本数为 2，策略值分别为 1 和 0。若 `undo` 提示没有可回滚版本，通常是环境准备时没有等待初始版本稳定就应用了失败更新；按 `环境准备.md` 的重练步骤重建本题资源。
