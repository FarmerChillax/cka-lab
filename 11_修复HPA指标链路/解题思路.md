# 第 11 题：解题思路与答案详解

## 关键技术难点

1. HPA 显示 `<unknown>` 可能同时来自 Metrics API 不可用和容器未设置 CPU request，必须分层排查。
2. kind 节点 kubelet 的服务证书通常不能通过其 InternalIP 校验；本地实验可给 Metrics Server 增加 `--kubelet-insecure-tls`。
3. CPU `Utilization` 是当前用量相对于 request 的百分比，没有 request 就无法计算。

## 解题思路

先检查 APIService condition 与 Metrics Server 日志，恢复 `kubectl top`；再检查 HPA condition 和目标 Deployment 的 resources。两层都修复后等待至少两个 HPA 同步周期。

## 答案详解

```sh
kubectl describe apiservice v1beta1.metrics.k8s.io
kubectl -n kube-system logs deployment/metrics-server --tail=50
kubectl -n kube-system patch deployment metrics-server --type=json \
  -p='[{"op":"add","path":"/spec/template/spec/containers/0/args/-","value":"--kubelet-insecure-tls"}]'
kubectl -n kube-system rollout status deployment/metrics-server --timeout=120s
kubectl wait --for=condition=Available apiservice/v1beta1.metrics.k8s.io --timeout=120s
kubectl top nodes
```

然后为目标容器补充计算利用率所需的 request 及题目指定 limit：

```sh
kubectl -n cka-scale set resources deployment scale-api -c server \
  --requests=cpu=10m,memory=16Mi \
  --limits=cpu=200m,memory=64Mi
kubectl -n cka-scale rollout status deployment/scale-api --timeout=120s
kubectl -n cka-scale describe hpa scale-api
kubectl -n cka-scale get hpa scale-api -w
```

看到 TARGETS 变成数值后退出观察并运行验收命令。若 APIService 已 Available 但 HPA 仍为 unknown，查看 HPA events 是否为 `FailedGetResourceMetric`；若只有部分 Pod 缺指标，确认新 ReplicaSet 的所有容器都配置了 CPU request。
