# 第 11 题：修复 HPA 指标链路

**建议用时：** 22 分钟。**Context：** `kind-cka-lab`。**命名空间：** `cka-scale`。

**操作入口：** `kubectl config use-context kind-cka-lab`

## 题目主干

`HorizontalPodAutoscaler/scale-api` 无法取得 CPU 利用率。排查并修复从 kubelet 到 Metrics API，再到 HPA 的完整链路，满足以下要求：

- `APIService/v1beta1.metrics.k8s.io` 的 `Available` condition 为 `True`，`kubectl top nodes` 能返回所有节点指标。
- 修复时保留 Metrics Server 现有参数，并增加适用于本地 kind kubelet 证书的参数；不要关闭 APIService 到 Metrics Server 的聚合层 TLS 校验以外的认证授权机制。
- 为 `Deployment/scale-api` 的 `server` 容器设置 CPU request `10m`、内存 request `16Mi`，以及 CPU limit `200m`、内存 limit `64Mi`。
- 保留 HPA 的 CPU 目标 50%、副本范围 2–5 和 60 秒缩容稳定窗口。最终 TARGETS 不得为 `<unknown>`，至少 2 个副本 Ready。

官方参考：[Resource Metrics Pipeline](https://kubernetes.io/docs/tasks/debug/debug-cluster/resource-metrics-pipeline/) 与 [Horizontal Pod Autoscaling](https://kubernetes.io/docs/concepts/workloads/autoscaling/horizontal-pod-autoscale/)。

## 验收标准

```sh
kubectl wait --for=condition=Available apiservice/v1beta1.metrics.k8s.io --timeout=120s
kubectl top nodes
kubectl -n cka-scale get hpa scale-api
kubectl -n cka-scale get deploy scale-api
kubectl -n cka-scale get deploy scale-api -o jsonpath='{.spec.template.spec.containers[?(@.name=="server")].resources}{"\n"}'
```

HPA 的 TARGETS 应显示数值百分比，Deployment 的 READY 至少为 `2/2`，资源请求和限制必须与题目一致。
