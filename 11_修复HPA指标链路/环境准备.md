# 环境准备：修复 HPA 指标链路

需要 `kind` v0.33.0 或更新版本、`kubectl` 和已启动的 kind 兼容容器运行时。本题沿用 `cka-lab` 集群；已有集群时跳过创建。

```sh
cd 11_修复HPA指标链路
kind create cluster --name cka-lab --config kind-config.yaml --wait 5m  # 仅在集群不存在时执行
kubectl config use-context kind-cka-lab
kubectl apply -f metrics-server.yaml
kubectl apply -f setup.yaml
kubectl -n cka-scale rollout status deployment/scale-api --timeout=120s
kubectl -n cka-scale wait --for=condition=Ready pod/load-generator --timeout=120s
```

[metrics-server.yaml](metrics-server.yaml) 是本题故障环境的一部分，固定使用 Metrics Server v0.9.0；它故意缺少 kind 所需的 kubelet TLS 参数。`setup.yaml` 中的目标 Deployment 也故意缺少 CPU request。不要在准备阶段修复它们。

等待约 30 秒后确认故障现象，再开始 22 分钟计时：

```sh
kubectl get apiservice v1beta1.metrics.k8s.io
kubectl top nodes
kubectl -n cka-scale get hpa scale-api
```

Metrics API 应不可用或尚未就绪，HPA 的 TARGETS 应包含 `<unknown>`。重练时重新应用两份初始清单：

```sh
kubectl apply -f metrics-server.yaml
kubectl delete namespace cka-scale --ignore-not-found --wait=true
kubectl apply -f setup.yaml
```
