# 环境准备 · 为 CoreDNS 配置内部静态域名

准备 kind v0.33.0 或更新版本、kubectl 和已启动的容器运行时。kind 自动选择可用的 Docker、Podman 或 nerdctl。先进入本题目录。已有 `cka-dns35` 集群时可跳过创建。

```sh
cd 35_为CoreDNS配置内部静态域名
kind create cluster --name cka-dns35 --config kind-config.yaml --wait 5m
```

用 [kind-config.yaml](kind-config.yaml) 创建集群后，应用 [setup.yaml](setup.yaml) 并确认初始状态。

```sh
kubectl config use-context kind-cka-dns35
kubectl apply -f setup.yaml
kubectl -n kube-system rollout status deployment/coredns --timeout=120s
kubectl -n cka-35 wait --for=condition=Ready pod/dns-probe --timeout=120s
kubectl -n cka-35 exec dns-probe -- nslookup kubernetes.default.svc.cluster.local.
```

本题会修改集群 DNS，因此使用独立的 `cka-dns35`。正常解析 Kubernetes Service、练习域未配置后再计时。

重练时用 `kind delete cluster --name cka-dns35` 删除本题独立集群，再用本页命令创建。
