# 第 25 题 · 诊断 OOM 并修正内存边界

建议用时 18 分钟，环境准备完成后开始计时。

操作入口 `kubectl config use-context kind-cka-next`。Context 为 `kind-cka-next`，命名空间为 `cka-25`。

## 题目主干

Deployment `parser` 在启动时反复退出。把容器最近一次退出原因保存到本机当前目录的 `parser.reason`，然后按容量评估将内存 request 调整为 128Mi、limit 调整为 160Mi。保留镜像、启动命令、容器名与副本数。

## 官方参考

- [容器资源管理](https://kubernetes.io/docs/concepts/configuration/manage-resources-containers/) · 内存 request、limit 和 OOM。
- [Pod Lifecycle](https://kubernetes.io/docs/concepts/workloads/pods/pod-lifecycle/) · 查看容器的退出状态。

## 验收标准

```sh
cat parser.reason
kubectl -n cka-25 rollout status deploy/parser --timeout=120s
kubectl -n cka-25 get deploy parser -o jsonpath='{.spec.template.spec.containers[0].resources}{"\n"}'
kubectl -n cka-25 logs deploy/parser
```

原退出原因为 OOMKilled，新模板的 request 与 limit 符合要求，当前日志包含 parser ready。
