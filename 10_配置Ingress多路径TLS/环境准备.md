# 环境准备：配置 Ingress 多路径 TLS

需要 `kind` v0.33.0 或更新版本、`kubectl`、`openssl` 和已启动的 kind 兼容容器运行时。本题沿用 `cka-lab` 集群；已有集群时跳过创建。

```sh
cd 10_配置Ingress多路径TLS
kind create cluster --name cka-lab --config kind-config.yaml --wait 5m  # 仅在集群不存在时执行
kubectl config use-context kind-cka-lab
kubectl apply -f ingress-controller.yaml
kubectl -n ingress-nginx rollout status deployment/ingress-nginx-controller --timeout=180s
kubectl apply -f setup.yaml
kubectl -n cka-edge rollout status deployment/web --timeout=120s
kubectl -n cka-edge rollout status deployment/api --timeout=120s
kubectl -n cka-edge wait --for=condition=Ready pod/ingress-probe --timeout=120s
```

`ingress-controller.yaml` 固定使用 ingress-nginx 最终发布线的 `v1.15.1`，仅用于本地练习；该项目已经归档，不应据此选择生产控制器。用于签发本题自签名证书的配置保存在 [tls/openssl.cnf](tls/openssl.cnf)，答题前不要创建证书、TLS Secret 或 Ingress。

确认后开始 22 分钟计时：

```sh
kubectl get ingressclass nginx
kubectl -n cka-edge get deploy,svc,pod
kubectl -n cka-edge get ingress,secret portal-tls
```

最后一条命令应显示资源不存在。重练时删除答题产生的资源，并重新应用后端：

```sh
kubectl -n cka-edge delete ingress portal --ignore-not-found
kubectl -n cka-edge delete secret portal-tls --ignore-not-found
kubectl apply -f setup.yaml
```
