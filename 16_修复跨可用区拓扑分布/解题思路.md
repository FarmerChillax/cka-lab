# 第 16 题：解题思路

## 关键技术难点

拓扑分布约束位于 Pod 模板的 `spec.topologySpreadConstraints`。`DoNotSchedule` 是硬约束；`ScheduleAnyway` 只是调度评分偏好。`labelSelector` 必须与 Pod 模板标签匹配，否则调度器不会把同一 Deployment 的 Pod 纳入偏差计算。

## 答案详解

编辑 Deployment，在 `spec.template.spec` 下加入：

```yaml
topologySpreadConstraints:
- maxSkew: 1
  topologyKey: topology.kubernetes.io/zone
  whenUnsatisfiable: DoNotSchedule
  labelSelector:
    matchLabels:
      app: api
```

可直接使用 patch：

```sh
kubectl -n cka-topology patch deployment api --type=strategic \
  -p='{"spec":{"template":{"spec":{"topologySpreadConstraints":[{"maxSkew":1,"topologyKey":"topology.kubernetes.io/zone","whenUnsatisfiable":"DoNotSchedule","labelSelector":{"matchLabels":{"app":"api"}}}]}}}}'
kubectl -n cka-topology rollout status deployment/api
```

检查节点所属区域及 Pod 分布：

```sh
kubectl get nodes -L topology.kubernetes.io/zone
kubectl -n cka-topology get pods -l app=api -o wide
```

两个区域都有符合条件的可调度节点，4 个副本在 `maxSkew: 1` 下只能形成 2:2 分布。若有 Pod Pending，使用 `kubectl describe pod` 检查节点标签、污点和 selector。
