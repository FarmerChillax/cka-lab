# 第 8 题：解题思路与答案详解

## 关键技术难点

1. `apiextensions.k8s.io/v1` 的 CRD 需要结构化 OpenAPI schema；在 `spec` 下标记 `required`，并给每个声明字段标明类型。
2. `status` 是子资源；开启后，普通 spec 写入与 status 写入分开。
3. `additionalPrinterColumns` 的 JSONPath 指向实例字段，不是 CRD 本身的字段。

## 解题思路

先定义 CRD 的名称、版本、scope 和 schema；等待 Established，再创建实例。最后分别检查打印列、schema 对非法值的拒绝，以及 status 子资源写入结果。

## 答案详解

保存为临时文件 `widget-crd.yaml`：

```yaml
apiVersion: apiextensions.k8s.io/v1
kind: CustomResourceDefinition
metadata:
  name: widgets.lab.cka.example
spec:
  group: lab.cka.example
  scope: Namespaced
  names:
    plural: widgets
    singular: widget
    kind: Widget
    listKind: WidgetList
  versions:
  - name: v1
    served: true
    storage: true
    schema:
      openAPIV3Schema:
        type: object
        required: [spec]
        properties:
          spec:
            type: object
            required: [image, replicas]
            properties:
              image:
                type: string
                minLength: 1
              replicas:
                type: integer
                minimum: 1
                maximum: 5
          status:
            type: object
            properties:
              readyReplicas:
                type: integer
                minimum: 0
    subresources:
      status: {}
    additionalPrinterColumns:
    - name: Desired
      type: integer
      jsonPath: .spec.replicas
```

保存为临时文件 `widget-demo.yaml`：

```yaml
apiVersion: lab.cka.example/v1
kind: Widget
metadata:
  name: demo
  namespace: cka-ext
spec:
  image: nginx:1.27.5
  replicas: 3
```

应用并验证：

```sh
kubectl apply -f widget-crd.yaml
kubectl wait --for=condition=Established crd/widgets.lab.cka.example --timeout=60s
kubectl apply -f widget-demo.yaml
kubectl -n cka-ext patch widget demo --subresource=status --type=merge \
  -p='{"status":{"readyReplicas":2}}'
kubectl -n cka-ext get widgets
kubectl -n cka-ext get widget demo -o yaml
kubectl -n cka-ext patch widget demo --type=merge \
  -p='{"spec":{"replicas":0}}' --dry-run=server
```

最后一条命令失败是正确结果；它不应修改现有实例。若实例创建时报资源类型不存在，确认 CRD 名称、group、version，并等待 `Established`。本题没有 controller，因此 `readyReplicas: 2` 是为测试 status 子资源手动写入的示例状态。
