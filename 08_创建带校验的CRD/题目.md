# 第 8 题：创建带校验的 CRD

**建议用时：** 20 分钟。**Context：** `kind-cka-lab`。**命名空间：** `cka-ext`。

**操作入口：** `kubectl config use-context kind-cka-lab`

## 题目主干

为集群定义 namespaced 自定义资源 `Widget`：API group 为 `lab.cka.example`，版本为 `v1`，复数资源名为 `widgets`，CRD 名为 `widgets.lab.cka.example`。结构化 schema 要求 `spec.image` 是非空字符串，`spec.replicas` 是 **1–5** 的整数，且这两个字段必填。启用 `/status` 子资源，其中 `status.readyReplicas` 为非负整数。为 `kubectl get widgets` 添加名为 `Desired` 的打印列，显示 `spec.replicas`。

然后在 `cka-ext` 创建 `Widget/demo`，设置 `image: nginx:1.27.5`、`replicas: 3`。验证把 `replicas` 改为 0 会被 API 拒绝，并通过 `/status` 子资源将 `readyReplicas` 设为 2。不要创建 Deployment 或安装 controller。

## 题面引用信息

| 项目 | 给定值 |
| --- | --- |
| CRD / Kind | `widgets.lab.cka.example` / `Widget` |
| Group / Version / Scope | `lab.cka.example` / `v1` / Namespaced |
| 必填字段 | `spec.image`、`spec.replicas` |
| 数值范围 | `spec.replicas` 为 1–5；`status.readyReplicas` ≥ 0 |
| 实例 | `cka-ext/demo`，镜像 `nginx:1.27.5`，副本数 3 |

官方参考：[CustomResourceDefinition](https://kubernetes.io/docs/tasks/extend-kubernetes/custom-resources/custom-resource-definitions/) 中的 **Specifying a structural schema**、**Validation**、**Status subresource** 和 **Additional printer columns**。

## 验收标准

```sh
kubectl wait --for=condition=Established crd/widgets.lab.cka.example --timeout=60s
kubectl -n cka-ext get widgets
kubectl -n cka-ext get widget demo -o yaml
kubectl -n cka-ext patch widget demo --type=merge \
  -p='{"spec":{"replicas":0}}' --dry-run=server
```

`kubectl get widgets` 应显示 `Desired` 列为 3；实例的 `status.readyReplicas` 应为 2；最后一条命令**预期失败**并报告 replicas 小于最小值，且实际实例仍保持 `replicas: 3`。
